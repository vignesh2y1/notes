## 🧠 Section A: Mathematical & Statistical Foundations

### Solution 1: Mathematical Proof of Merge Event Bias

#### 1. Deterministic CPM Calculation
Given $X_1 \sim \text{Uniform}(10, 20)$ and $X_2 \sim \text{Uniform}(10, 20)$:
$$\mathbb{E}[X_1] = \frac{10 + 20}{2} = 15, \quad \mathbb{E}[X_2] = \frac{10 + 20}{2} = 15$$
In deterministic CPM:
$$T_{\text{CPM}} = \max(\mathbb{E}[X_1], \mathbb{E}[X_2]) = \max(15, 15) = 15\text{ days}$$

#### 2. CDF and PDF Derivation for $T = \max(X_1, X_2)$
For $t \in [10, 20]$, the CDF of a uniform variable $X_i \sim U(10, 20)$ is:
$$F_X(t) = P(X_i \le t) = \frac{t - 10}{20 - 10} = \frac{t - 10}{10}$$

Because $X_1$ and $X_2$ are independent:
$$F_T(t) = P(\max(X_1, X_2) \le t) = P(X_1 \le t \text{ and } X_2 \le t) = P(X_1 \le t) \cdot P(X_2 \le t)$$
$$F_T(t) = \left( \frac{t - 10}{10} \right)^2 = \frac{(t - 10)^2}{100}$$

Differentiating with respect to $t$ gives the PDF $f_T(t)$:
$$f_T(t) = \frac{d}{dt} F_T(t) = \frac{2(t - 10)}{100} = \frac{t - 10}{50} \quad \text{for } 10 \le t \le 20$$

#### 3. True Mathematical Expectation $\mathbb{E}[T]$
$$\mathbb{E}[T] = \int_{10}^{20} t \cdot f_T(t) \, dt = \int_{10}^{20} t \left( \frac{t - 10}{50} \right) \, dt = \frac{1}{50} \int_{10}^{20} (t^2 - 10t) \, dt$$

Evaluating the definite integral:
$$\int_{10}^{20} t^2 \, dt = \left[ \frac{t^3}{3} \right]_{10}^{20} = \frac{8000 - 1000}{3} = \frac{7000}{3}$$
$$\int_{10}^{20} 10t \, dt = \left[ 5t^2 \right]_{10}^{20} = 5(400 - 100) = 1500 = \frac{4500}{3}$$
$$\int_{10}^{20} (t^2 - 10t) \, dt = \frac{7000 - 4500}{3} = \frac{2500}{3}$$
$$\mathbb{E}[T] = \frac{1}{50} \times \frac{2500}{3} = \frac{50}{3} \approx 16.667\text{ days}$$

$$\text{Deterministic Error} = \frac{16.667 - 15.000}{15.000} \times 100\% = +11.11\%$$
The deterministic CPM schedule understates the expected milestone completion by **1.67 days (11.1%)** on just two parallel paths!

#### 4. Three Parallel Merging Paths ($k = 3$)
For $T_3 = \max(X_1, X_2, X_3)$:
$$F_{T_3}(t) = \left( \frac{t - 10}{10} \right)^3 = \frac{(t - 10)^3}{1000}$$
$$f_{T_3}(t) = \frac{3(t - 10)^2}{1000}$$
Using substitution $u = t - 10 \implies t = u + 10, du = dt$, with limits $u \in [0, 10]$:
$$\mathbb{E}[T_3] = \int_0^{10} (u + 10) \frac{3u^2}{1000} \, du = \frac{3}{1000} \int_0^{10} (u^3 + 10u^2) \, du$$
$$\int_0^{10} u^3 \, du = \frac{10^4}{4} = 2500, \quad \int_0^{10} 10u^2 \, du = 10 \times \frac{1000}{3} = \frac{10000}{3}$$
$$2500 + \frac{10000}{3} = \frac{17500}{3}$$
$$\mathbb{E}[T_3] = \frac{3}{1000} \times \frac{17500}{3} = 17.50\text{ days}$$
The expected duration expands from 15.0 days to **17.50 days**—an error of **+16.67%**!

### Solution 2: Jensen's Inequality Application in Schedule Networks

#### 1. Statement of Jensen's Inequality
Let $\mathbf{X}$ be an $n$-dimensional random vector and $g: \mathbb{R}^n \to \mathbb{R}$ be a convex function. If $\mathbb{E}[\mathbf{X}]$ and $\mathbb{E}[g(\mathbf{X})]$ exist, then:
$$\mathbb{E}[g(\mathbf{X})] \ge g(\mathbb{E}[\mathbf{X}])$$

#### 2. Proof of Convexity for the Multivariate Max Function
Let $g(\mathbf{x}) = \max(x_1, x_2, \dots, x_k)$. We must show that for any vectors $\mathbf{x}, \mathbf{y} \in \mathbb{R}^k$ and scalar $\lambda \in [0, 1]$:
$$g(\lambda \mathbf{x} + (1 - \lambda)\mathbf{y}) \le \lambda g(\mathbf{x}) + (1 - \lambda)g(\mathbf{y})$$

For any individual coordinate index $i \in \{1, 2, \dots, k\}$:
$$\lambda x_i + (1 - \lambda)y_i \le \lambda \max_{j} x_j + (1 - \lambda)\max_{j} y_j$$
Since this holds for every coordinate $i$, it must hold for the maximum over all coordinates:
$$\max_{i} [\lambda x_i + (1 - \lambda)y_i] \le \lambda \max_{j} x_j + (1 - \lambda)\max_{j} y_j$$
$$\iff g(\lambda \mathbf{x} + (1 - \lambda)\mathbf{y}) \le \lambda g(\mathbf{x}) + (1 - \lambda)g(\mathbf{y})$$
Thus, the maximum function $g$ is strictly **convex**.

#### 3. Project Duration Lower Bound Proof
In any CPM network, the project completion duration is the maximum of the path durations:
$$T_{\text{project}}(\mathbf{D}) = \max_{p \in \text{Paths}} \left( \sum_{i \in p} D_i \right)$$
Since a sum of linear terms is linear, and the maximum of convex/linear functions is convex, the entire CPM operator $T_{\text{project}}(\mathbf{D})$ is a **convex function** of the activity duration vector $\mathbf{D}$.

Applying Jensen's Inequality:
$$\mathbb{E}[T_{\text{project}}(\mathbf{D})] \ge T_{\text{project}}(\mathbb{E}[\mathbf{D}]) = \text{CPM}(\mathbb{E}[\mathbf{D}])$$
Hence, deterministic CPM scheduling is mathematically proven to always return a value **less than or equal to** the true expected project duration. It can never overestimate the project timeline.

### Solution 3: Beta-PERT vs. Triangular Distribution Derivations

Given three-point estimates: $a = 10$, $m = 12$, $b = 26$.

#### 1. Standard PERT Formula
$$\mu_{\text{PERT}} = \frac{a + 4m + b}{6} = \frac{10 + 4(12) + 26}{6} = \frac{10 + 48 + 26}{6} = \frac{84}{6} = 14.0\text{ days}$$
$$\sigma_{\text{PERT}} = \frac{b - a}{6} = \frac{26 - 10}{6} = \frac{16}{6} \approx 2.67\text{ days}$$
$$\text{Var}_{\text{PERT}} = \sigma^2 \approx 7.11$$

#### 2. Triangular Distribution
$$\mu_{\text{Tri}} = \frac{a + m + b}{3} = \frac{10 + 12 + 26}{3} = \frac{48}{3} = 16.0\text{ days}$$
$$\text{Var}_{\text{Tri}} = \frac{a^2 + m^2 + b^2 - ab - am - bm}{18}$$
$$10^2 + 12^2 + 26^2 = 100 + 144 + 676 = 920$$
$$ab + am + bm = (10 \times 26) + (10 \times 12) + (12 \times 26) = 260 + 120 + 312 = 692$$
$$\text{Var}_{\text{Tri}} = \frac{920 - 692}{18} = \frac{228}{18} \approx 12.67$$
$$\sigma_{\text{Tri}} = \sqrt{12.67} \approx 3.56\text{ days}$$

#### 3. Why Triangular Produces Higher Variance & Heavy Tails
* **Weighting:** The PERT mean weights the most likely value $m$ with a factor of 4 ($\frac{4}{6} = 66.7\%$), whereas Triangular weights $m$ equally with $a$ and $b$ ($\frac{1}{3} = 33.3\%$).
* **Geometry:** Triangular density drops linearly from the peak $m$ to endpoints $a$ and $b$, maintaining substantial probability density near the extreme tails. Beta-PERT has asymptotic bell-shaped shoulders that rapidly taper to zero at the bounds, concentrating probability mass tightly around $m$.

#### 4. Beta-PERT Shape Parameters
$$\alpha_1 = 1 + 4 \left( \frac{m - a}{b - a} \right) = 1 + 4 \left( \frac{12 - 10}{26 - 10} \right) = 1 + 4 \left( \frac{2}{16} \right) = 1 + 0.5 = 1.5$$
$$\alpha_2 = 1 + 4 \left( \frac{b - m}{b - a} \right) = 1 + 4 \left( \frac{26 - 12}{26 - 10} \right) = 1 + 4 \left( \frac{14}{16} \right) = 1 + 3.5 = 4.5$$
The distribution is $\text{Beta}(\alpha_1 = 1.5, \alpha_2 = 4.5)$ scaled across $[10, 26]$.

### Solution 4: Inverse Transform Sampling Mechanics

#### 1. Mathematical Principle
Let $X$ be a random variable with continuous, strictly increasing CDF $F(x) = P(X \le x)$. If $U \sim \text{Uniform}(0, 1)$, then the transformed variable $X = F^{-1}(U)$ has exactly the distribution $F$.
$$P(F^{-1}(U) \le x) = P(U \le F(x)) = F(x)$$

#### 2. Derivation for Triangular Distribution $T(a, m, b)$
The CDF of $T(a, m, b)$ is:
$$F(x) = \begin{cases} 
\frac{(x - a)^2}{(b - a)(m - a)} & \text{for } a \le x \le m \\ 
1 - \frac{(b - x)^2}{(b - a)(b - m)} & \text{for } m < x \le b 
\end{cases}$$
The cutoff CDF value at $x = m$ is $F(m) = \frac{m - a}{b - a}$.

* **Region 1: When $U < \frac{m - a}{b - a}$:**
  $$U = \frac{(x - a)^2}{(b - a)(m - a)} \implies (x - a)^2 = U(b - a)(m - a)$$
  $$x = a + \sqrt{U(b - a)(m - a)}$$
* **Region 2: When $U \ge \frac{m - a}{b - a}$:**
  $$U = 1 - \frac{(b - x)^2}{(b - a)(b - m)} \implies 1 - U = \frac{(b - x)^2}{(b - a)(b - m)}$$
  $$x = b - \sqrt{(1 - U)(b - a)(b - m)}$$

#### 3. Calculation for $a=5, m=10, b=20, U=0.25$
* Cutoff: $\frac{m - a}{b - a} = \frac{10 - 5}{20 - 5} = \frac{5}{15} = \frac{1}{3} \approx 0.3333$.
* Since $U = 0.25 < 0.3333$, we use Region 1:
  $$x = 5 + \sqrt{0.25 \times (20 - 5) \times (10 - 5)} = 5 + \sqrt{0.25 \times 15 \times 5} = 5 + \sqrt{18.75} \approx 5 + 4.330 = 9.33\text{ days}$$

## 🏗️ Section B: Enterprise Risk Engineering & Surya 100MW Scenarios

### Solution 5: Surya 100MW Solar IPP — Sizing the Grid Contingency Buffer

#### 1. Why Deterministic Buffer is Illusory
In deterministic CPM, the project finishes on Day 145 ($m = 145$ on Branch B). The apparent buffer against the 180-day deadline is $180 - 145 = 35$ days.
However, both branches have heavy right-skewed pessimistic tails ($b = 190$ on Branch A, $b = 210$ on Branch B). Because they merge at COD, an overrun on **either** branch delays COD. The probability that both branches simultaneously finish $\le 145$ days is significantly less than 50% ($P(\text{Branch A} \le 140) \approx 0.5$, $P(\text{Branch B} \le 145) \approx 0.5 \implies 0.5 \times 0.5 = 0.25$).

#### 2. Sizing the Schedule Contingency Buffer
* Deterministic Date = Day 145.
* $P_{50}$ (Median) = Day 156.
* $P_{80}$ (Enterprise Commitment) = Day 178.
* Statutory Deadline = Day 180.

$$\text{Statistical Contingency Buffer} = P_{80} - \text{Deterministic Date} = 178 - 145 = 33\text{ calendar days}$$
Surya Infra should inject a formal 33-day **Schedule Contingency Buffer** into their contractual baseline. This sets the committed baseline finish to Day 178, safely within the 180-day statutory limit.

#### 3. Contractual Risk of $P_{50}$ vs. $P_{80}$
* **Committing to $P_{50}$ (Day 156):** Implies a **50% probability of default**. Half of all simulated futures result in late delivery. In an EPC solar contract with liquidated damages of ₹2.5 Million/day, a 50% default risk is financially reckless.
* **Committing to $P_{80}$ (Day 178):** Provides an 80% confidence level, meaning there is only a 20% residual risk of exceeding the date. Project finance lenders and credit rating agencies generally mandate $P_{80}$ for debt-service covenant approvals.

### Solution 6: Criticality Index vs. Deterministic Float Paradox

#### 1. Activity A Criticality Index
Activity A has $TF = 0$ deterministically, but its duration variance is minimal: $[29, 30, 31]$. Its completion time is virtually guaranteed between Day 29 and Day 31.
However, parallel Activity B has massive variance: $[10, 20, 65]$.
Whenever Activity B samples a duration $> 45$ days (since $30 + 15 = 45$), Activity B overtakes Activity A and drives the finish of Substation Erection.
Therefore, Activity A will **not** have a 100% Criticality Index. In fact, whenever B overruns, B becomes critical and A accumulates float!

#### 2. Why Activity B Has a 68% Criticality Index Despite 15 Days Float
Although Activity B has 15 days of deterministic float, its upper tail extends to 65 days.
* In the PERT distribution $[10, 20, 65]$, the upper tail probability mass $P(\text{Duration} > 35)$ is substantial.
* In 68% of the Monte Carlo iterations, the sampled duration of B exceeds the sampled duration of A by more than 15 days.
* In all those iterations, Activity B drives the merge milestone, giving it $\text{CI} = 68\%$.

#### 3. Mitigation Budget Allocation
The project risk manager must allocate mitigation capital to **Activity B (Customs Clearance)**:
* Activity A has virtually zero duration variance ($\sigma \approx 0.33$ days); optimizing it cannot protect the project completion date.
* Activity B is the true risk driver ($\text{CI} = 68\%$, variance $\sigma \approx 9.17$ days). Pre-clearing customs bonds, paying for expedited port handling, or engaging specialized customs brokers directly reduces the tail risk that threatens COD.

### Solution 7: Cruciality and Schedule Sensitivity Index (SSI)

#### 1. Criticality Index (CI) vs. Cruciality
* **Criticality Index ($\text{CI}$):** A frequency measure: the percentage of iterations in which the activity was on the critical path ($0 \le \text{CI} \le 100\%$). It does not measure *how much* the activity's delay influenced the project completion date.
* **Cruciality ($\rho$):** A correlation measure: the Pearson or Spearman correlation coefficient between the activity's duration and the total project duration ($-1 \le \rho \le 1$).

#### 2. High CI but Low Cruciality Scenario
Consider a mandatory regulatory filing task:
- Duration: $D \sim \text{Uniform}(1.9, 2.1)$ days.
- It sits directly on the critical path because all predecessor tasks flow through it, so $\text{CI} = 100\%$.
- However, its variance is tiny ($\pm 0.1$ day). The total project duration varies by $\pm 60$ days due to excavation and procurement risks.
- The correlation $\text{Corr}(D_{\text{filing}}, T_{\text{project}}) \approx 0$.
- Hence, the task has **100% Criticality Index**, but **0.0 Cruciality**. Trying to expedite this task will have zero impact on total project volatility!

#### 3. Schedule Sensitivity Index (SSI)
$$\text{SSI}_i = \frac{\sigma_{D_i}}{\sigma_{T_{\text{project}}}} \times \text{CI}_i$$
SSI penalizes activities that are critical but have negligible variance, and promotes activities that combine high criticality with high duration variance.

## 💻 Section C: Engine Architecture & Golang Multi-Core Optimization

### Solution 8: Lock-Free PRNG in Multi-Goroutine Simulations

#### 1. Why `rand.Float64()` Degrades on Multi-Core
In Go's `math/rand` (pre-v2), package-level functions use a single global shared generator protected by an internal mutex:
```go
// Standard library internal implementation:
func (r *lockedSource) Int63() (n int64) {
    r.lk.Lock()
    n = r.src.Int63()
    r.lk.Unlock()
    return
}
```
When 8 or 16 CPU cores attempt to generate millions of random numbers simultaneously, cache-line bouncing and lock contention paralyze the CPU cores, reducing throughput by 80–90%.

#### 2. Resolving the Bottleneck
In modern Go (Go 1.22+), `math/rand/v2` provides thread-safe lock-free top-level functions or explicit `rand.NewPCG(seed1, seed2)` instances. In classic Go, allocate an explicit `rand.New(rand.NewSource(seed))` inside each worker goroutine.

#### 3. Production Go Worker Implementation
```go
package sra

import (
	"math/rand"
	"sync"
	"time"
)

func RunParallelWorkers(numWorkers, itersPerWorker int) []float64 {
	var wg sync.WaitGroup
	results := make([][]float64, numWorkers)

	for w := 0; w < numWorkers; w++ {
		wg.Add(1)
		go func(workerID int) {
			defer wg.Done()
			// Thread-local PRNG with unique non-overlapping seed
			seed := time.Now().UnixNano() + int64(workerID*31337)
			localRNG := rand.New(rand.NewSource(seed))

			localResults := make([]float64, itersPerWorker)
			for i := 0; i < itersPerWorker; i++ {
				// Pure lock-free execution
				localResults[i] = localRNG.Float64()
			}
			results[workerID] = localResults
		}(w)
	}

	wg.Wait()
	// Flatten results...
	return nil
}
```

### Solution 9: Pre-Allocated DAG Topological Traversal in Go

#### 1. Eliminating Allocations in Inner Loops
At 100,000 iterations, allocating a single slice or map inside the loop causes 100,000 garbage collection pauses, evicting CPU L1/L2 data caches. Pre-allocating flat primitive buffers ensures zero GC overhead.

#### 2. Memory Layout & Cache-Friendly Forward Pass
```go
package sra

// FlatGraph stores DAG topology as contiguous integer slices.
type FlatGraph struct {
	NumNodes      int
	// Predecessor CSR (Compressed Sparse Row) representation
	PredOffsets   []int   // Offset into PredIndices for each node
	PredCounts    []int   // Number of predecessors for each node
	PredIndices   []int   // Contiguous predecessor node indices
	
	// Pre-allocated worker scratch buffers
	Durations     []float64
	EarlyFinishes []float64
}

// ForwardPass executes the CPM forward pass with zero heap allocations.
func (g *FlatGraph) ForwardPass() float64 {
	var maxProjectFinish float64

	// Nodes are strictly ordered in topological order 0..NumNodes-1
	for i := 0; i < g.NumNodes; i++ {
		var maxPredEF float64
		offset := g.PredOffsets[i]
		count := g.PredCounts[i]

		for p := 0; p < count; p++ {
			predIdx := g.PredIndices[offset+p]
			if g.EarlyFinishes[predIdx] > maxPredEF {
				maxPredEF = g.EarlyFinishes[predIdx]
			}
		}

		ef := maxPredEF + g.Durations[i]
		g.EarlyFinishes[i] = ef
		if ef > maxProjectFinish {
			maxProjectFinish = ef
		}
	}

	return maxProjectFinish
}
```

### Solution 10: SRA Results Aggregator & Welford's Algorithm

#### 1. Quantile Interpolation in Go
```go
package sra

import (
	"math"
	"sort"
)

func ComputePercentiles(durations []float64, targets []float64) map[float64]float64 {
	sort.Float64s(durations)
	n := len(durations)
	results := make(map[float64]float64)

	for _, p := range targets {
		if p <= 0 {
			results[p] = durations[0]
			continue
		}
		if p >= 1.0 {
			results[p] = durations[n-1]
			continue
		}

		pos := p * float64(n-1)
		low := int(math.Floor(pos))
		high := int(math.Ceil(pos))
		weight := pos - float64(low)

		interpolated := durations[low]*(1.0-weight) + durations[high]*weight
		results[p] = interpolated
	}

	return results
}
```

#### 2. Single-Pass Welford's Algorithm for Mean and Variance
```go
package sra

import "math"

type RunningStats struct {
	count int
	mean  float64
	m2    float64
}

func (s *RunningStats) Update(val float64) {
	s.count++
	delta := val - s.mean
	s.mean += delta / float64(s.count)
	delta2 := val - s.mean
	s.m2 += delta * delta2
}

func (s *RunningStats) Mean() float64 {
	return s.mean
}

func (s *RunningStats) Variance() float64 {
	if s.count < 2 {
		return 0.0
	}
	return s.m2 / float64(s.count-1)
}

func (s *RunningStats) StdDev() float64 {
	return math.Sqrt(s.Variance())
}
```
Welford's algorithm avoids storing all 100,000 floating-point numbers in memory while completely preventing floating-point catastrophic cancellation.
