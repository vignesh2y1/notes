## 🧠 Section A: Conceptual & Architectural Principles

### Solution 1: The Named-Individual Trap vs Generic Role Pools

#### 1. Three Critical Business and Project Controls Risks
1. **Employee Attrition & Staffing Churn:**
   On a multi-year EPC infrastructure project, employee turnover typically ranges from 15% to 25% annually. If 120 testing activities 14 months away are tied to "Rajesh Sharma", his resignation forces manual search-and-replace across hundreds of activities. If unaddressed, historical reports link progress to an inactive user account.
2. **Artificial Bottlenecks and False Over-Allocations:**
   When named individuals are assigned across multiple simultaneous bids or projects, enterprise resource leveling algorithms treat that specific human as a hard constraint. The engine delays project completion dates even when the organization has dozens of equally qualified SCADA engineers available in the contractor pool.
3. **Loss of Enterprise Capacity Visibility:**
   Executives cannot assess organizational capability to take on new projects. A query asking *"Do we have enough SCADA commissioning capacity in Q4 2026?"* fails because the demand is scattered across individual employee names rather than aggregated under a standardized capability trade pool (`ENG-ELEC-SCADA`).

#### 2. How Roles Decouple Demand from Supply
* **Roles (Demand Contract):** Define *what* qualification is needed, the estimated hours, and a standard budgetary billing rate (e.g., ₹4,000/hr). This allows CPM scheduling, baseline freezing, and cost budgeting to proceed independently of HR staffing.
* **Resources (Supply Instance):** Represent *who* will actually do the work. Concrete resources are assigned only during the 2-to-4 week lookahead window prior to physical execution.

#### 3. Go Software Engineering Analogy: Interfaces vs Concrete Structs
```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                            SOFTWARE INTERFACES VS CONCRETE INSTANCES                             │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│  Go Type System:                                                                                 │
│  type ScadaEngineer interface {                                                                  │
│      ConfigureRTU(rackID int) error         ◄─── ROLE: Contract / Required Capability            │
│  }                                                                                               │
│                                                                                                  │
│  type RajeshSharma struct { HourlyRate float64 }                                                 │
│  func (r *RajeshSharma) ConfigureRTU(id int) error { ... } ◄── RESOURCE: Concrete Struct         │
│                                                                                                  │
│  High-level scheduling engine depends on ScadaEngineer, NOT RajeshSharma!                        │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### Solution 2: The Three Resource Types & Engine Invariants

#### 1. Unit of Measure (UOM) Invariants
* **Labor & Non-Labor:** Default and immutable UOM is **Time / Hours** (`HR`). Humans and machinery operate across working shifts, calendars, and hours per day.
* **Material:** Has no calendar duration. Consumed in physical quantities. Must support user-defined UOMs:
  * Solar Panels: `EA` (Each) or `Wp` (Watts-peak)
  * Ready-Mix Concrete: `M3` (Cubic meters)
  * Steel Piles: `MT` (Metric tonnes)
  * Control Cabling: `LM` or `KM` (Linear meters / kilometers)

#### 2. Crane (Non-Labor) vs Crane Operator (Labor)
```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                            NON-LABOR VS LABOR OPERATIONAL SEPARATION                             │
├──────────────────────────┬───────────────────────────────┬───────────────────────────────────────┤
│ Attribute                │ Crane (Non-Labor)             │ Operator (Labor)                      │
├──────────────────────────┼───────────────────────────────┼───────────────────────────────────────┤
│ Resource ID              │ R-EQP-CRANE-100T              │ R-OPR-CRANE-01                        │
│ Base Calendar            │ 6-Day, 10-Hr (Machine limits) │ 6-Day, 8-Hr (Statutory labor limit)   │
│ Maintenance Window       │ Alternate Sundays (Oil/Lube)  │ Weekly rest day (Sunday off)          │
│ Cost Driver              │ Fuel + Depreciation + Lease   │ Base Wage + Overtime + Shift Premiums │
│ Overtime Applicability   │ Machine runtime rate          │ 1.5x / 2.0x Statutory Overtime        │
└──────────────────────────┴───────────────────────────────┴───────────────────────────────────────┘
```
Conflating them prevents tracking fuel/lease costs separately from union labor overtime and hides machine-breakdown vs operator-absence variances.

#### 3. Material Accidentally Configured as Labor
* **The Error:** 240,000 solar panels entered as `RT_Labor` instead of `RT_Mat`.
* **Mathematical Disaster:**
  $$\text{Total Hours} = 240,000\text{ hours}$$
  If the installation window is 30 calendar days (240 working hours):
  $$\text{Peak Labor Demand} = \frac{240,000\text{ hrs}}{240\text{ hrs/person}} = 1,000\text{ full-time electricians!}$$
  The resource histogram will show a catastrophic 1,000-man labor spike, distorting labor camp sizing, transport logistics, and project cash flows.

### Solution 3: Primary Role vs Multi-Role Assignments

#### 1. Purpose of the `is_primary` Flag
When an employee possesses multiple competencies (e.g., Priya Nair qualified in High Voltage Testing and Safety Auditing), she appears in both role pools. The `is_primary` flag designates her **main organizational trade**. When enterprise reports compute total company headcounts by trade, only primary roles are counted, ensuring:
$$\sum \text{Primary Role Allocations} = \text{Total Active Employees}$$

#### 2. Preventing Double-Counting During Roll-Ups
If Priya is working on a safety audit (`ENG-SAFETY-AUD`, secondary role), the scheduling engine credits her hours to that project task. However, when the Enterprise Capacity Planner evaluates global hiring needs:
* Priya's capacity is deducted from `ENG-ELEC-HV` (primary) because she is unavailable for HV testing.
* The system does not report Priya as two distinct persons.

#### 3. P6 Competency Scale (1 to 5)
* `1 - Master` (Highest technical authority, can supervise and certify)
* `2 - Expert` (Autonomous execution of complex tasks)
* `3 - Proficient` (Standard qualified engineer/technician)
* `4 - Competent` (Junior engineer working under guidance)
* `5 - Novice` (Apprentice/trainee)

Matching algorithm rule:
$$\text{Candidate Qualified} \iff \text{Candidate.SkillLevel} \le \text{RoleAssignment.RequiredSkillLevel}$$

### Solution 4: Calendar Interplay — Task Dependent vs Resource Dependent

#### 1. Task Dependent (`TT_Task`)
* **Governing Calendar:** Activity Calendar (6-Day: Mon–Sat, 8 hrs/day).
* **Work Schedule:**
  * Day 1: Friday, 08:00 to 17:00 (8 hrs worked, 8 hrs remaining).
  * Day 2: Saturday, 08:00 to 17:00 (8 hrs worked, 0 hrs remaining).
* **Early Finish:** **Saturday at 17:00**.
* **Anomaly:** Arun Kumar's calendar has Saturday as non-working. P6 still forces the assignment to occur on Saturday. Arun Kumar is flagged with **8 hours of Over-Allocation** on Saturday. The activity finish date **does not slip**.

#### 2. Resource Dependent (`TT_Rsrc`)
* **Governing Calendar:** Arun Kumar's Calendar (5-Day: Mon–Fri, 8 hrs/day).
* **Work Schedule:**
  * Day 1: Friday, 08:00 to 17:00 (8 hrs worked, 8 hrs remaining).
  * Saturday & Sunday: Non-working for Arun Kumar (0 hrs worked).
  * Day 2: Monday, 08:00 to 17:00 (8 hrs worked, 0 hrs remaining).
* **Early Finish:** **Monday at 17:00**.
* **Calendar Days Elapsed:** 4 calendar days (Fri, Sat, Sun, Mon). The activity slips by 2 days because the human resource is unavailable.

#### 3. When to Mandate `TT_Rsrc`
Mandate `Resource Dependent` when:
1. The activity is strictly bounded by human specialist or unique heavy machine availability (e.g., specialized foreign commissioning engineer or heavy 500-ton hydraulic jack).
2. The work cannot legally or physically proceed without that specific resource's physical presence.

### Solution 5: The Double-Calendar Subcontractor Gridlock

#### 1. What Anomaly Occurs Over the Weekend?
If `TT_Rsrc` is set and both resources are driving:
* P6 calculates the daily working hours as the **intersection** of all driving resource calendars:
  $$\text{WorkingHours}_{\text{day}} = \min(\text{RigHours}_{\text{day}}, \text{InspectorHours}_{\text{day}})$$
* On Saturday and Sunday, $\text{InspectorHours} = 0$.
* Therefore, the engine calculates 0 hours worked for the entire activity over the weekend! The multi-million-rupee piling rig is forced to sit idle on Saturday and Sunday in the schedule model, destroying subcontractor productivity and triggering claims.

#### 2. Re-architecting the Activity Network
Decouple the continuous physical construction from the contractual inspection milestone:

### Solution 6: Driving vs Non-Driving Resource Mechanics

#### 1. Identification of Driving vs Non-Driving Resources
* **Resource A (Oil Filtration Plant, Non-Labor, 24/7):** **Driving**. The machine runs continuously for 72 hours.
* **Resource B (Shift Electricians, Labor, 3 Rotating Crews):** **Driving** (or covered under a 24/7 shift calendar).
* **Resource C (Junior Trainee, Labor, 5-Day corporate calendar):** **Non-Driving**. The trainee's absence must never halt high-voltage transformer commissioning.

#### 2. Accidental Driving Flag on Resource C
If Resource C is flagged as Driving on a `Resource Dependent` activity:
* On Friday at 17:00, Resource C's calendar stops.
* The entire 72-hour filtration activity pauses until Monday at 08:00!
* The schedule slips by 63 hours, incorrectly predicting that a continuous 3-day technical process takes over 5.5 calendar days.

### Solution 7: Role Substitution & Commercial Cost Variance

#### 1. Planned Budgeted Cost (BCWS)
$$\text{Budgeted Cost} = 40\text{ hrs} \times ₹3,200/\text{hr} = ₹1,28,000$$

#### 2. Revised Forecast Cost (with Dr. Harsh Vardhan)
$$\text{Forecast Cost} = 40\text{ hrs} \times ₹4,500/\text{hr} = ₹1,80,000$$

#### 3. Unit Rate Variance ($Cost_{variance}$)
$$\text{Cost Variance} = \text{Budgeted Cost} - \text{Forecast Cost} = ₹1,28,000 - ₹1,80,000 = -₹52,000$$
$$\text{Rate Variance per Hour} = ₹3,200 - ₹4,500 = -₹1,300/\text{hr}$$
* **Commercial Verdict:** **Unfavorable variance of ₹52,000** (Cost Overrun). The EPC contractor must absorb this negative margin unless reimbursable under an approved client change order.

## 💻 Section C: Database & Engine Engineering

### Solution 8: Relational Integrity in Enterprise Resource Schemas

#### 1. Purpose of the `chk_rsrc_or_role` Constraint
```sql
CONSTRAINT chk_rsrc_or_role CHECK (
    (rsrc_id IS NOT NULL AND role_id IS NULL) OR 
    (rsrc_id IS NULL AND role_id IS NOT NULL)
)
```
* **Enforcement:** Enforces an **exclusive-OR (XOR)** relationship.
* **Business Rule:** A rate entry in `rsrc_rates` must either be a **Resource Rate** (hourly wage of a specific human or machine) OR a **Role Rate** (standard budgetary rate for a generic skill pool). It cannot be both, and it cannot be neither.

#### 2. SQL Query: Detect Orphaned Role Assignments
```sql
SELECT 
    tr.task_rsrc_id,
    tr.task_id,
    r.role_code,
    r.role_name
FROM task_rsrc tr
JOIN roles r ON tr.role_id = r.role_id
WHERE tr.rsrc_id IS NULL -- Still unstaffed
  AND NOT EXISTS (
      -- Check if any active resource possesses this role
      SELECT 1 
      FROM rsrc_role rr
      JOIN rsrc res ON rr.rsrc_id = res.rsrc_id
      WHERE rr.role_id = tr.role_id
        AND res.active_flag = TRUE
  );
```

### Solution 9: Time-Phased Rate Escalation Query

```sql
-- Resolves the effective rate for a resource as of target_date
SELECT 
    r.rsrc_code,
    r.rsrc_name,
    rr.rate_type,
    rr.cost_per_qty AS effective_rate,
    rr.cost_per_qty_ot AS effective_ot_rate,
    rr.start_date AS rate_effective_from
FROM rsrc r
JOIN LATERAL (
    SELECT cost_per_qty, cost_per_qty_ot, start_date, rate_type
    FROM rsrc_rates
    WHERE rsrc_id = r.rsrc_id
      AND rate_type = 1 -- Standard Rate Tier
      AND start_date <= '2026-11-15 00:00:00+00'::TIMESTAMPTZ -- Target Execution Date
    ORDER BY start_date DESC
    LIMIT 1
) rr ON TRUE
WHERE r.rsrc_code = 'R-ENG-09';
```

### Solution 10: Go Engine Calendar Intersection Algorithm

```go
package main

import (
	"errors"
	"fmt"
	"time"
)

type Calendar struct {
	ID          string
	WorkingDays map[time.Weekday]bool
	HoursPerDay float64
}

type Resource struct {
	ID       string
	Name     string
	Calendar *Calendar
}

type Assignment struct {
	Resource  *Resource
	IsDriving bool
}

type Activity struct {
	ID           string
	PlannedHours float64
	StartDate    time.Time
	Assignments  []*Assignment
}

// CalculateResourceIntersectionDuration computes required calendar days by finding common working hours.
func CalculateResourceIntersectionDuration(act *Activity) (int, time.Time, error) {
	if act == nil {
		return 0, time.Time{}, errors.New("activity cannot be nil")
	}
	if act.PlannedHours <= 0 {
		return 0, act.StartDate, nil
	}

	// Filter driving resources with valid calendars
	var drivingCalendars []*Calendar
	for _, asgn := range act.Assignments {
		if asgn.IsDriving && asgn.Resource != nil && asgn.Resource.Calendar != nil {
			drivingCalendars = append(drivingCalendars, asgn.Resource.Calendar)
		}
	}

	if len(drivingCalendars) == 0 {
		return 0, time.Time{}, errors.New("no driving resource calendars found")
	}

	accumulatedHours := 0.0
	currDate := act.StartDate
	calendarDays := 0

	for accumulatedHours < act.PlannedHours {
		calendarDays++
		// Find intersection of working hours on currDate
		dayHours := 24.0 // Upper bound
		isCommonWorkDay := true

		for _, cal := range drivingCalendars {
			if !cal.WorkingDays[currDate.Weekday()] {
				isCommonWorkDay = false
				break
			}
			if cal.HoursPerDay < dayHours {
				dayHours = cal.HoursPerDay
			}
		}

		if isCommonWorkDay {
			accumulatedHours += dayHours
		}

		if accumulatedHours >= act.PlannedHours {
			break
		}
		currDate = currDate.AddDate(0, 0, 1)
	}

	return calendarDays, currDate, nil
}

func main() {
	// Subcontractor Piling Rig (7-Day, 10 hrs/day)
	calRig := &Calendar{
		ID: "CAL-RIG-7D",
		WorkingDays: map[time.Weekday]bool{
			time.Monday: true, time.Tuesday: true, time.Wednesday: true,
			time.Thursday: true, time.Friday: true, time.Saturday: true,
			time.Sunday: true,
		},
		HoursPerDay: 10.0,
	}

	// QA Inspector (5-Day, 8 hrs/day)
	calInspector := &Calendar{
		ID: "CAL-QA-5D",
		WorkingDays: map[time.Weekday]bool{
			time.Monday: true, time.Tuesday: true, time.Wednesday: true,
			time.Thursday: true, time.Friday: true,
			time.Saturday: false, time.Sunday: false,
		},
		HoursPerDay: 8.0,
	}

	rig := &Resource{ID: "RIG-02", Name: "Hydraulic Piling Rig #02", Calendar: calRig}
	inspector := &Resource{ID: "QA-01", Name: "TPIA Chief QA Inspector", Calendar: calInspector}

	// Scenario: 40 hours of pile driving starting on Friday
	start := time.Date(2026, time.May, 1, 0, 0, 0, 0, time.UTC) // Friday

	// Case A: Rig alone
	actSolo := &Activity{
		PlannedHours: 40.0,
		StartDate:    start,
		Assignments: []*Assignment{
			{Resource: rig, IsDriving: true},
		},
	}
	daysSolo, finishSolo, _ := CalculateResourceIntersectionDuration(actSolo)
	fmt.Printf("Rig Alone: %d Calendar Days (Finishes %s, %s)\n",
		daysSolo, finishSolo.Weekday(), finishSolo.Format("02-Jan-2006"))

	// Case B: Rig + QA Inspector both driving (Intersected Calendar)
	actBoth := &Activity{
		PlannedHours: 40.0,
		StartDate:    start,
		Assignments: []*Assignment{
			{Resource: rig, IsDriving: true},
			{Resource: inspector, IsDriving: true},
		},
	}
	daysBoth, finishBoth, _ := CalculateResourceIntersectionDuration(actBoth)
	fmt.Printf("Rig + QA Inspector Intersected: %d Calendar Days (Finishes %s, %s)\n",
		daysBoth, finishBoth.Weekday(), finishBoth.Format("02-Jan-2006"))
}
```
