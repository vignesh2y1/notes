# Topic 7.2: Resource Assignments & Duration Types — The Scheduling Mechanics

---

## 1. Executive Summary & The Core Mental Model

### 1.1 The Triad of Scheduling Physics
In any resource-loaded scheduling engine, every activity assignment is governed by three fundamental physical variables:
1. **Duration ($D$):** The working time span (in hours or days) over which the work is executed.
2. **Total Units ($U$):** The total physical effort or quantity consumed (labor hours, machine hours, or material units like tons of steel).
3. **Units / Time ($R$):** The rate of application of the resource (units per hour or units per day; e.g., 8 hrs/day, 2 rigs/day, 50 $m^3$/day).

These three variables are permanently locked together by the **Fundamental Scheduling Equation**:

$$\text{Units } (U) = \text{Duration } (D) \times \text{Units / Time } (R)$$

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                            THE SCHEDULING TRIAD (PHYSICS EQUATION)                               │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│                                  Total Units (U)                                                 │
│                                   [Work / Hours]                                                 │
│                                         ▲                                                        │
│                                        / \                                                       │
│                                       /   \                                                      │
│                                      /  =  \                                                     │
│                                     /       \                                                    │
│                                    /    *    \                                                   │
│                                   ▼           ▼                                                  │
│                       Duration (D) ◄─────────► Units / Time (R)                                  │
│                      [Working Days]              [Rate / Intensity]                              │
│                                                                                                  │
│  THE MATHEMATICAL LAW:                                                                           │
│  Three variables with one constraint: U = D * R.                                                 │
│  You CANNOT fix all three variables simultaneously when one changes.                            │
│  When a scheduler edits ONE variable, the software MUST hold ONE constant and RECALCULATE       │
│  the THIRD.                                                                                      │
│                                                                                                  │
│  THE P6 DURATION TYPE SETTING DETERMINES WHICH VARIABLE IS HELD CONSTANT!                        │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

> **The Core Axiom:**  
> In mathematics, an equation with 3 variables ($U = D \times R$) has 2 degrees of freedom. When an end-user changes one variable, the system must decide which of the remaining two absorbs the impact. **Duration Type** is not a cosmetic label—it is the deterministic state machine configuration that governs which variable is locked and which variable recalculates.

### 1.3 Running Case Study Context: Surya 100MW Solar IPP
On the Surya Solar Project:
* **Tracker Piling (32,000 piles):** Pure production work. The total work ($U$) is fixed. If we mobilize 4 hydraulic rigs instead of 2 (increasing $R$), the duration ($D$) should drop by 50%. This mandates **Fixed Units**.
* **Supervisory Engineering (Site Management):** The Site Project Manager and Safety Officers must be present for the full duration of the activity. If the activity slips from 10 days to 20 days, their hours ($U$) must double at their standard 8 hrs/day rate ($R$). This mandates **Fixed Duration & Units/Time**.
* **Subcontractor Lump-Sum Package:** 220kV Transformer Testing subcontract has a fixed 14-day testing window and a fixed 112 man-hour lump-sum budget. Adjusting crew assignments must not alter the contractual 14-day duration or the 112-hour budget. This mandates **Fixed Duration & Units**.

## 2. The Four Primavera P6 Duration Types

Primavera P6 provides four distinct Duration Types. Every activity must have exactly one Duration Type assigned.

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐

├────────────────────────────┬─────────────────────────────┬───────────────────────────────────────┤
│ Duration Type Name         │ Locked / Invariant Entity   │ Typical Industrial Application        │
├────────────────────────────┼─────────────────────────────┼───────────────────────────────────────┤
│ 1. Fixed Duration &        │ Duration (D) AND            │ Contractual fixed-window tasks,       │
│    Units                   │ Total Units (U)             │ lump-sum subcontracts, level-of-      │
```

### 2.1 Fixed Duration & Units (`DT_FixDurUnits`)
* **Core Rule:** Duration and Total Units remain constant.
* **When Duration is modified:** Units/Time is recalculated:
  $$R = \frac{U}{D}$$
* **When Units are modified:** Units/Time is recalculated:
  $$R = \frac{U}{D}$$
* **When an additional resource is assigned:** Duration does **NOT** change. Total activity units remain fixed, and units are divided among the assigned resources.
* **Best Practice:** Use for time-sensitive, budget-capped milestones and professional services subcontracts.

### 2.2 Fixed Duration & Units/Time (`DT_FixDurQtyTime`)
* **Core Rule:** Duration and the daily rate (Units/Time) remain constant.
* **When Duration is modified:** Total Units are recalculated:
  $$U = D \times R$$
* **When Units/Time is modified:** Total Units are recalculated:
  $$U = D \times R$$
* **When Units are modified:** Duration remains constant, and Units/Time is recalculated:
  $$R = \frac{U}{D}$$
* **Best Practice:** Use for tasks with fixed daily burn rates, ongoing supervision (Resident Engineers, Security, HSE Officers), or equipment leased on a daily/monthly basis.

### 2.3 Fixed Units (`DT_FixQty`)
* **Core Rule:** Total Units (work quantity) remain constant.
* **When Duration is modified:** Units/Time is recalculated:
  $$R = \frac{U}{D}$$
* **When Units/Time is modified:** Duration is recalculated:
  $$D = \frac{U}{R}$$
* **When an additional resource is assigned:** Duration decreases! This implements the classic engineering axiom: *"Adding more qualified hands to a production task finishes the job faster."*
* **Best Practice:** Mandated for all physical quantity-driven construction tasks (e.g., excavating 10,000 $m^3$ of desert earth, installing 240,000 PV modules).

### 2.4 Fixed Units/Time (`DT_FixQtyTime`)
* **Core Rule:** The daily production rate ($R$) is constant.
* **When Duration is modified:** Total Units are recalculated:
  $$U = D \times R$$
* **When Total Units are modified:** Duration is recalculated:
  $$D = \frac{U}{R}$$
* **When an additional resource is assigned:** Total Units increase, but duration remains unchanged (unless the combined crew rate is altered).
* **Best Practice:** Use when work is constrained by specialized plant throughput (e.g., an on-site batching plant with a maximum output of 45 $m^3$/hour).

## 4. Resource Spread Curves (Non-Linear Distribution)

By default, scheduling engines assume **Linear Spread**: work is divided equally across every working day ($R_{\text{day}} = U / D$). 

In physical reality, work is almost never linear:
* Construction begins slowly with mobilization and safety briefings, peaks during full production, and tapers off during inspection and punch-listing.
* Material procurement is front-loaded (upfront advance for long-lead manufacturing).
* Testing and commissioning are back-loaded.

## 6. Production Go Calculation Engine

Below is a complete, production-grade Go engine demonstrating:
1. Exact Duration Type recalculations according to the State Transition Matrix.
2. Resource Curve interpolation distributing total units across daily working buckets.

```go
package main

import (
	"errors"
	"fmt"
	"math"
)

// DurationType defines how the scheduling triad (U = D * R) recalculates.
type DurationType string

const (
	FixedDurationAndUnits     DurationType = "DT_FixDurUnits"
	FixedDurationAndUnitsTime DurationType = "DT_FixDurQtyTime"
	FixedUnits                DurationType = "DT_FixQty"
	FixedUnitsTime            DurationType = "DT_FixQtyTime"
)

// ResourceCurve holds the 21-point incremental percentage distribution.
type ResourceCurve struct {
	ID     string
	Code   string
	Values [21]float64 // Sum must equal 100.0%
}

// Assignment represents a resource assigned to a task.
type Assignment struct {
	ID          string
	DurationHrs float64 // D
	TotalUnits  float64 // U
	UnitsPerHr  float64 // R
	Curve       *ResourceCurve
}

// Task represents an activity governed by a DurationType.
type Task struct {
	ID           string
	Code         string
	DurationType DurationType
	Assignment   *Assignment
}

// Recalculator encapsulates the duration type state machine logic.
type Recalculator struct{}

func NewRecalculator() *Recalculator {
	return &Recalculator{}
}

// UpdateDuration updates duration and recalculates the other parameters based on DurationType.
func (r *Recalculator) UpdateDuration(task *Task, newDurationHrs float64) error {
	if newDurationHrs <= 0 {
		return errors.New("duration must be greater than zero")
	}
	asgn := task.Assignment
	asgn.DurationHrs = newDurationHrs

	switch task.DurationType {
	case FixedDurationAndUnits:
		// U is locked -> R recalculates: R = U / D
		asgn.UnitsPerHr = asgn.TotalUnits / asgn.DurationHrs

	case FixedDurationAndUnitsTime:
		// R is locked -> U recalculates: U = D * R
		asgn.TotalUnits = asgn.DurationHrs * asgn.UnitsPerHr

	case FixedUnits:
		// U is locked -> R recalculates: R = U / D
		asgn.UnitsPerHr = asgn.TotalUnits / asgn.DurationHrs

	case FixedUnitsTime:
		// R is locked -> U recalculates: U = D * R
		asgn.TotalUnits = asgn.DurationHrs * asgn.UnitsPerHr
	}
	return nil
}

// UpdateUnits updates total units and recalculates based on DurationType.
func (r *Recalculator) UpdateUnits(task *Task, newUnits float64) error {
	if newUnits < 0 {
		return errors.New("units cannot be negative")
	}
	asgn := task.Assignment
	asgn.TotalUnits = newUnits

	switch task.DurationType {
	case FixedDurationAndUnits:
		// D is locked -> R recalculates: R = U / D
		asgn.UnitsPerHr = asgn.TotalUnits / asgn.DurationHrs

	case FixedDurationAndUnitsTime:
		// D is locked -> R recalculates: R = U / D
		asgn.UnitsPerHr = asgn.TotalUnits / asgn.DurationHrs

	case FixedUnits:
		// R is locked -> D recalculates: D = U / R
		asgn.DurationHrs = asgn.TotalUnits / asgn.UnitsPerHr

	case FixedUnitsTime:
		// R is locked -> D recalculates: D = U / R
		asgn.DurationHrs = asgn.TotalUnits / asgn.UnitsPerHr
	}
	return nil
}

// UpdateUnitsPerHr updates rate and recalculates based on DurationType.
func (r *Recalculator) UpdateUnitsPerHr(task *Task, newRate float64) error {
	if newRate <= 0 {
		return errors.New("units per hour must be greater than zero")
	}
	asgn := task.Assignment
	asgn.UnitsPerHr = newRate

	switch task.DurationType {
	case FixedDurationAndUnits:
		// D is locked -> U recalculates: U = D * R
		asgn.TotalUnits = asgn.DurationHrs * asgn.UnitsPerHr

	case FixedDurationAndUnitsTime:
		// D is locked -> U recalculates: U = D * R
		asgn.TotalUnits = asgn.DurationHrs * asgn.UnitsPerHr

	case FixedUnits:
		// U is locked -> D recalculates: D = U / R
		asgn.DurationHrs = asgn.TotalUnits / asgn.UnitsPerHr

	case FixedUnitsTime:
		// D is locked -> U recalculates: U = D * R
		asgn.TotalUnits = asgn.DurationHrs * asgn.UnitsPerHr
	}
	return nil
}

// DistributeCurveUnits calculates the time-spread daily bucket allocations using a 21-point curve.
func (r *Recalculator) DistributeCurveUnits(asgn *Assignment, numWorkingDays int) ([]float64, error) {
	if numWorkingDays <= 0 {
		return nil, errors.New("numWorkingDays must be positive")
	}
	dailyBuckets := make([]float64, numWorkingDays)

	// If no curve assigned, distribute linearly
	if asgn.Curve == nil {
		linearDaily := asgn.TotalUnits / float64(numWorkingDays)
		for i := 0; i < numWorkingDays; i++ {
			dailyBuckets[i] = linearDaily
		}
		return dailyBuckets, nil
	}

	// 21-point cumulative interpolation
	cumulativeCurve := make([]float64, 21)
	runningSum := 0.0
	for i, v := range asgn.Curve.Values {
		runningSum += v
		cumulativeCurve[i] = runningSum
	}

	prevCumulativeUnits := 0.0
	for day := 1; day <= numWorkingDays; day++ {
		// Calculate percentage of duration elapsed at end of day
		pctElapsed := (float64(day) / float64(numWorkingDays)) * 100.0

		// Find interpolation points in 21-point curve (each segment = 5%)
		curveIndex := int(pctElapsed / 5.0)
		if curveIndex >= 20 {
			curveIndex = 19
		}

		// Linear interpolation between curveIndex and curveIndex+1
		x0 := float64(curveIndex) * 5.0
		y0 := cumulativeCurve[curveIndex]
		y1 := cumulativeCurve[curveIndex+1]
		interpolatedPct := y0 + ((pctElapsed-x0)/5.0)*(y1-y0)

		if day == numWorkingDays {
			interpolatedPct = 100.0 // Ensure 100% closure
		}

		cumUnits := (interpolatedPct / 100.0) * asgn.TotalUnits
		dailyBuckets[day-1] = math.Round((cumUnits-prevCumulativeUnits)*100) / 100
		prevCumulativeUnits = cumUnits
	}

	return dailyBuckets, nil
}

func main() {
	calc := NewRecalculator()

	// 1. Surya Solar Tracker Piling: Fixed Units (32,000 piles / 1,600 hrs work)
	pilingTask := &Task{
		ID:           "TASK-PILE-01",
		Code:         "TRACKER-PILING",
		DurationType: FixedUnits,
		Assignment: &Assignment{
			DurationHrs: 160.0, // 20 working days @ 8 hrs/day
			TotalUnits:  1600.0, // 1600 machine hours
			UnitsPerHr:  10.0,   // 10 machine-hours per clock hour (10 rigs)
		},
	}

	fmt.Println("--- SCENARIO 1: FIXED UNITS (ADDING EQUIPMENT) ---")
	fmt.Printf("Initial: Duration=%.1f hrs (%.1f days), Units=%.1f, Rate=%.1f rigs\n",
		pilingTask.Assignment.DurationHrs, pilingTask.Assignment.DurationHrs/8.0,
		pilingTask.Assignment.TotalUnits, pilingTask.Assignment.UnitsPerHr)

	// Mobilize 10 additional rigs (Rate increases from 10 to 20 rigs)
	_ = calc.UpdateUnitsPerHr(pilingTask, 20.0)
	fmt.Printf("After Adding Rigs (Rate=20): Duration=%.1f hrs (%.1f days)! (Units locked at %.1f)\n\n",
```

## 7. Real-World Pitfalls & Production Edge Cases

### 7.1 The "Accidental Duration Explosion" Anti-Pattern
* **The Trap:** An engineer sets an activity to **Fixed Units/Time** or **Fixed Duration & Units/Time**. Later, to compress the project critical path, they assign two additional electrical crews.
* **The Disaster:** Instead of shortening the duration, P6 maintains the duration and simply triples the budgeted man-hours and cost! 
* **The Rule:** If your objective is "crashing" the schedule (adding resources to compress duration), the activity **MUST be set to Fixed Units** prior to adding resources.

### 7.2 Rounding Drift in Discrete 21-Point S-Curves
* **The Problem:** In integer or floating-point division across 21 points, truncating to two decimal places can result in cumulative spread summing to 99.98% or 100.02% of total units.
* **The Fix:** Implement an **endpoint closure reconciliation step**:
  $$\text{Units}_{\text{Final Day}} = \text{Total Units} - \sum_{i=1}^{N-1} \text{Units}_i$$
  This ensures that physical quantities and financial commitments match the contractual budget to the exact penny.
