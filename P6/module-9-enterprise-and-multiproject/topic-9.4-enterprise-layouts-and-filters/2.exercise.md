### Question 4: Dynamic Rolling Variables vs. Static Temporal Filters
Consider the following two filter definitions applied to the Surya 100MW Solar Project:
* **Filter A:** `Early Start >= '2026-06-01' AND Early Start <= '2026-06-15'`
* **Filter B:** `Early Start >= Data Date AND Early Start <= Data Date + 14d`
1. Contrast the behavior of Filter A versus Filter B when the monthly schedule update is run and the project Data Date advances from 01-Jun-2026 to 01-Jul-2026.
2. What is the semantic difference between `Data Date` and `Current Date`? In what engineering context would a scheduler filter by `Current Date` rather than `Data Date`?

### Question 6: Compiling Filter AST to Parameterized PostgreSQL SQL
Consider the following JSON filter AST:
```json
{
  "logic": "ALL",
  "predicates": [
    { "field": "discipline", "operator": "EQUALS", "value": "CIVIL" },
    { "field": "status", "operator": "NOT_EQUALS", "value": "COMPLETED" },
    { "field": "total_float", "operator": "LESS_THAN_OR_EQUAL", "value": 0 }
  ]
}
```
1. Write a function in Go or SQL that takes this AST and compiles it into a parameterized SQL `WHERE` clause:
   `WHERE (discipline = $1 AND status <> $2 AND total_float <= $3)`
2. How do you prevent SQL injection vulnerabilities when dynamically compiling arbitrary user-defined filter expressions into SQL queries?
3. If the filter includes a dynamic rolling variable (`Data Date + 14d`), show how the SQL compilation translates this into PostgreSQL date arithmetic (`p.data_date + INTERVAL '14 days'`).
