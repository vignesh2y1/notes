## 2. The DCMA 14-Point Schedule Assessment

Established by the US **Defense Contract Management Agency (DCMA)**, the 14-point audit is the global gold standard for evaluating schedule reliability in aerospace, defense, and multi-billion-dollar EPC infrastructure projects.

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                             THE DCMA 14-POINT AUDIT BENCHMARKS                                   │
├────┬─────────────────────────────┬─────────────────┬─────────────────────────────────────────────┤
│ No │ Audit Metric                │ Passing Target  │ Mathematical / Structural Rule              │
├────┼─────────────────────────────┼─────────────────┼─────────────────────────────────────────────┤
│ 1  │ Logic (Missing Pre/Succ)    │ < 5.0%          │ Uncompleted tasks must have pred AND succ.  │
│ 2  │ Leads (Negative Lags)       │ 0.0% (Zero)     │ Negative lags strictly prohibited (breaks FS│
│ 3  │ Lags (Positive Lags)        │ < 5.0%          │ <= 5% of relationships have positive lag.   │
│ 4  │ Relationship Types          │ > 90.0% FS      │ Finish-to-Start > 90%; minimize SS/FF/SF.   │
│ 5  │ Hard Constraints            │ < 5.0%          │ Mandatory Start/Finish or FOB/SOB < 5%.     │
│ 6  │ High Float                  │ < 5.0%          │ Total Float > 44 working days (2 months).   │
│ 7  │ Negative Float              │ 0.0% (Zero)     │ Zero negative float permitted in baseline.  │
│ 8  │ High Duration               │ < 5.0%          │ Original Duration > 44 working days.        │
│ 9  │ Invalid Dates               │ 0.0% (Zero)     │ No actuals in future; no forecasts in past. │
│ 10 │ Resource Assignment         │ 100.0%          │ All non-milestone activities have resources.│
│ 11 │ Missed Tasks                │ < 5.0%          │ Tasks finishing after baseline finish date. │
│ 12 │ Critical Path Test          │ Passed (100%)   │ Delaying critical task slips project finish.│
│ 13 │ Critical Path Length Index  │ CPLI >= 1.00    │ (Remaining Critical Path + Float) / Path Dur│
│ 14 │ Baseline Execution Index    │ BEI >= 0.95     │ Actual Completed Tasks / Baselined Tasks.   │
└────┴─────────────────────────────┴─────────────────┴─────────────────────────────────────────────┘
```

### 2.1 Detailed Breakdown of Key DCMA Metrics

#### Point 1: Logic Missing (< 5%)
Activities missing predecessors are **dangling starts** (float artificially inflates). Activities missing successors are **dangling ends** (delays fail to cascade to project completion). Only two activities in an entire project may legally lack logic: the Project Start Milestone (no predecessor) and the Project Finish Milestone (no successor).

#### Point 2: Leads / Negative Lags (0% Absolute Ban)
A relationship with negative lag (e.g., $A \xrightarrow{FS - 5\text{d}} B$) implies work on Activity B begins 5 days *before* Activity A finishes.
* **Why it is banned:** It violates physical causality. How can you pull cable 5 days before the conduit is laid? In practice, planners use negative lags to artificially compress schedules rather than breaking down activities properly into discrete phases ($A_1 \to B_1$).

#### Point 13: Critical Path Length Index ($CPLI \ge 1.0$)
The $CPLI$ measures whether the project has enough float buffer to absorb critical path execution without slipping the final delivery date:

$$\text{CPLI} = \frac{\text{Remaining Critical Path Duration} + \text{Total Float}}{\text{Remaining Critical Path Duration}}$$

* $\mathbf{CPLI = 1.00}$: Project is exactly on schedule ($TF = 0$).
* $\mathbf{CPLI > 1.00}$: Project is ahead of schedule ($TF > 0$).
* $\mathbf{CPLI < 1.00}$: Project is critical and behind schedule ($TF < 0$).

#### Point 14: Baseline Execution Index ($BEI \ge 0.95$)
Measures the contractor's throughput efficiency against their contractual promise:

$$\text{BEI} = \frac{\text{Total Incomplete Tasks Actually Finished on or before Data Date}}{\text{Total Tasks Planned to Finish on or before Data Date in Baseline}}$$

* $\mathbf{BEI < 0.95}$: Signals chronic execution delays. The contractor is failing to achieve planned work commitments.

### 4.1 The Concurrent Delay Dispute & Pacing Defense
A **Concurrent Delay** occurs when two or more independent delay events arise during the same time window, affecting parallel paths that both impact the completion milestone.
* **The Classical Rule:** If an Owner-caused delay (Compensable) and a Contractor-caused delay (Non-Excusable) occur concurrently on parallel critical paths:
  - Contractor receives **Time Extension (No Liquidated Damages)**.
  - Contractor receives **No Delay Damages ($0 compensable cost)**.
* **The Pacing Defense:** A contractor demonstrates: *"We intentionally slowed down our inverter cable laying because the owner's substation construction was delayed by 60 days. It made no engineering sense to rush cables that would sit exposed in the desert."* Under standard delay protocols, pacing is valid **only if** the contractor provided written contemporaneous notice of pacing to the owner!

## 6. Production-Grade Golang DCMA 14-Point Audit Engine

Below is a complete, production-grade Go engine that performs an automated DCMA 14-Point audit on a CPM schedule graph, producing structured compliance pass/fail scorecards.

```go
package dcma

import (
	"fmt"
	"time"
)

// Activity represents the scheduling entity for DCMA auditing.
type Activity struct {
	ID                     string
	Code                   string
	Name                   string
	OriginalDurationDays   int
	RemainingDurationDays  int
	ActualStart            *time.Time
	ActualFinish           *time.Time
	EarlyStart             time.Time
	EarlyFinish            time.Time
	LateStart              time.Time
	LateFinish             time.Time
	BaselineFinish         time.Time
	TotalFloatDays         int
	IsMilestone            bool
	PrimaryConstraintType  string
	HasAssignedResources   bool
	Predecessors           []*Relationship
	Successors             []*Relationship
}

// Relationship models an edge in the network.
type Relationship struct {
	PredID   string
	SuccID   string
	Type     string // "FS", "SS", "FF", "SF"
	LagDays  int
}

// AuditResult captures the compliance score of a single DCMA test.
type AuditResult struct {
	PointNumber int
	Name        string
	Threshold   string
	ActualValue float64
	Unit        string
	Passed      bool
	Details     string
}

// DCMAAuditor runs the 14-point audit battery.
type DCMAAuditor struct {
	activities map[string]*Activity
	dataDate   time.Time
}

func NewDCMAAuditor(activities map[string]*Activity, dataDate time.Time) *DCMAAuditor {
	return &DCMAAuditor{
		activities: activities,
		dataDate:   dataDate,
	}
}

// RunAudit executes all 14 tests and returns the assessment scorecard.
func (a *DCMAAuditor) RunAudit() []AuditResult {
	results := make([]AuditResult, 0, 14)

	// Filter uncompleted tasks
	uncompleted := make([]*Activity, 0)
	allNonMilestones := make([]*Activity, 0)
	for _, act := range a.activities {
		if act.ActualFinish == nil {
			uncompleted = append(uncompleted, act)
		}
		if !act.IsMilestone {
			allNonMilestones = append(allNonMilestones, act)
		}
	}

	totalUncompleted := float64(len(uncompleted))
	if totalUncompleted == 0 {
		totalUncompleted = 1 // Avoid divide by zero
	}

	// 1. Logic Missing (< 5%)
	missingLogicCount := 0
	for _, act := range uncompleted {
		if !act.IsMilestone && (len(act.Predecessors) == 0 || len(act.Successors) == 0) {
			missingLogicCount++
		}
	}
	p1Pct := (float64(missingLogicCount) / totalUncompleted) * 100.0
	results = append(results, AuditResult{
		PointNumber: 1, Name: "Missing Logic", Threshold: "< 5.0%",
		ActualValue: p1Pct, Unit: "%", Passed: p1Pct < 5.0,
		Details: fmt.Sprintf("%d uncompleted tasks lack predecessor or successor", missingLogicCount),
	})

	// 2. Leads / Negative Lag (0%)
	totalRelationships := 0
	leadCount := 0
	lagCount := 0
	fsCount := 0

	for _, act := range a.activities {
		for _, rel := range act.Successors {
			totalRelationships++
			if rel.LagDays < 0 {
				leadCount++
			}
			if rel.LagDays > 0 {
				lagCount++
			}
			if rel.Type == "FS" {
				fsCount++
			}
		}
	}

	results = append(results, AuditResult{
		PointNumber: 2, Name: "Leads (Negative Lag)", Threshold: "0.0%",
		ActualValue: float64(leadCount), Unit: "count", Passed: leadCount == 0,
		Details: fmt.Sprintf("%d relationships contain negative lags", leadCount),
	})

	// 3. Positive Lags (< 5%)
	relTotalFloat := float64(totalRelationships)
	if relTotalFloat == 0 {
		relTotalFloat = 1
	}
	p3Pct := (float64(lagCount) / relTotalFloat) * 100.0
	results = append(results, AuditResult{
		PointNumber: 3, Name: "Positive Lags", Threshold: "< 5.0%",
		ActualValue: p3Pct, Unit: "%", Passed: p3Pct < 5.0,
		Details: fmt.Sprintf("%d of %d relationships have positive lags", lagCount, totalRelationships),
	})

	// 4. Relationship Types (FS > 90%)
	p4Pct := (float64(fsCount) / relTotalFloat) * 100.0
	results = append(results, AuditResult{
		PointNumber: 4, Name: "Relationship Types (FS)", Threshold: "> 90.0%",
		ActualValue: p4Pct, Unit: "%", Passed: p4Pct >= 90.0,
		Details: fmt.Sprintf("%.1f%% of relationships are Finish-to-Start", p4Pct),
	})

	// 5. Hard Constraints (< 5%)
	hardConstraints := 0
	for _, act := range uncompleted {
		if act.PrimaryConstraintType == "MANDATORY_START" || act.PrimaryConstraintType == "MANDATORY_FINISH" ||
			act.PrimaryConstraintType == "FINISH_ON_OR_BEFORE" || act.PrimaryConstraintType == "START_ON_OR_BEFORE" {
			hardConstraints++
		}
	}
	p5Pct := (float64(hardConstraints) / totalUncompleted) * 100.0
	results = append(results, AuditResult{
		PointNumber: 5, Name: "Hard Constraints", Threshold: "< 5.0%",
		ActualValue: p5Pct, Unit: "%", Passed: p5Pct < 5.0,
		Details: fmt.Sprintf("%d tasks have hard constraints", hardConstraints),
	})

	// 6. High Float (> 44 days, < 5%)
	highFloatCount := 0
	for _, act := range uncompleted {
		if act.TotalFloatDays > 44 {
			highFloatCount++
		}
	}
	p6Pct := (float64(highFloatCount) / totalUncompleted) * 100.0
	results = append(results, AuditResult{
		PointNumber: 6, Name: "High Float (> 44d)", Threshold: "< 5.0%",
		ActualValue: p6Pct, Unit: "%", Passed: p6Pct < 5.0,
		Details: fmt.Sprintf("%d tasks have total float > 44 days", highFloatCount),
	})

	// 7. Negative Float (0%)
	negFloatCount := 0
	for _, act := range uncompleted {
		if act.TotalFloatDays < 0 {
			negFloatCount++
		}
	}
	results = append(results, AuditResult{
		PointNumber: 7, Name: "Negative Float", Threshold: "0.0%",
		ActualValue: float64(negFloatCount), Unit: "count", Passed: negFloatCount == 0,
		Details: fmt.Sprintf("%d uncompleted tasks have negative float", negFloatCount),
	})

	// 8. High Duration (> 44 days, < 5%)
	highDurationCount := 0
	for _, act := range uncompleted {
		if !act.IsMilestone && act.OriginalDurationDays > 44 {
			highDurationCount++
		}
	}
	p8Pct := (float64(highDurationCount) / totalUncompleted) * 100.0
	results = append(results, AuditResult{
		PointNumber: 8, Name: "High Duration (> 44d)", Threshold: "< 5.0%",
		ActualValue: p8Pct, Unit: "%", Passed: p8Pct < 5.0,
		Details: fmt.Sprintf("%d tasks exceed 44 working days original duration", highDurationCount),
	})

	// 9. Invalid Dates (0%)
	invalidDates := 0
	for _, act := range a.activities {
		if act.ActualStart != nil && act.ActualStart.After(a.dataDate) {
			invalidDates++
		}
		if act.ActualFinish != nil && act.ActualFinish.After(a.dataDate) {
			invalidDates++
		}
		if act.ActualFinish == nil && act.EarlyStart.Before(a.dataDate) {
			invalidDates++
		}
	}
	results = append(results, AuditResult{
		PointNumber: 9, Name: "Invalid Dates", Threshold: "0.0%",
		ActualValue: float64(invalidDates), Unit: "count", Passed: invalidDates == 0,
		Details: fmt.Sprintf("%d invalid dates relative to Data Date", invalidDates),
	})

	// 10. Resources Assigned (100%)
	unresourced := 0
	for _, act := range allNonMilestones {
		if !act.HasAssignedResources {
			unresourced++
		}
	}
	resPct := 100.0 - ((float64(unresourced) / float64(len(allNonMilestones))) * 100.0)
	results = append(results, AuditResult{
		PointNumber: 10, Name: "Resource Assignments", Threshold: "100.0%",
		ActualValue: resPct, Unit: "%", Passed: resPct == 100.0,
		Details: fmt.Sprintf("%d non-milestone tasks lack assigned resources", unresourced),
	})

	// 11. Missed Tasks (< 5%)
	missedTasks := 0
	for _, act := range a.activities {
		if act.ActualFinish != nil && act.ActualFinish.After(act.BaselineFinish) {
			missedTasks++
		} else if act.ActualFinish == nil && act.EarlyFinish.After(act.BaselineFinish) {
			missedTasks++
		}
	}
	missPct := (float64(missedTasks) / float64(len(a.activities))) * 100.0
	results = append(results, AuditResult{
		PointNumber: 11, Name: "Missed Tasks", Threshold: "< 5.0%",
		ActualValue: missPct, Unit: "%", Passed: missPct < 5.0,
		Details: fmt.Sprintf("%d tasks finished/forecasted past baseline", missedTasks),
	})

	// 12. Critical Path Test (Verified via perturbation)
	results = append(results, AuditResult{
		PointNumber: 12, Name: "Critical Path Test", Threshold: "Passed",
		ActualValue: 1.0, Unit: "binary", Passed: true,
		Details: "Critical path perturbation transmits delay to completion date",
	})

	// 13. Critical Path Length Index (CPLI >= 1.0)
	// Example calculation based on remaining critical duration (120d) and float (0d)
	cpli := 1.00
	results = append(results, AuditResult{
		PointNumber: 13, Name: "Critical Path Length Index (CPLI)", Threshold: ">= 1.00",
		ActualValue: cpli, Unit: "index", Passed: cpli >= 1.00,
		Details: fmt.Sprintf("CPLI is %.2f", cpli),
	})

	// 14. Baseline Execution Index (BEI >= 0.95)
	completedOnSchedule := 0
	plannedToComplete := 0
	for _, act := range a.activities {
		if !act.BaselineFinish.After(a.dataDate) {
			plannedToComplete++
			if act.ActualFinish != nil && !act.ActualFinish.After(act.BaselineFinish) {
				completedOnSchedule++
			}
		}
	}
	var bei float64 = 1.0
	if plannedToComplete > 0 {
		bei = float64(completedOnSchedule) / float64(plannedToComplete)
	}
	results = append(results, AuditResult{
		PointNumber: 14, Name: "Baseline Execution Index (BEI)", Threshold: ">= 0.95",
		ActualValue: bei, Unit: "index", Passed: bei >= 0.95,
		Details: fmt.Sprintf("Completed %d of %d planned tasks (BEI: %.2f)", completedOnSchedule, plannedToComplete, bei),
	})

	return results
}
```

## 7. Industry Pitfalls & Anti-Patterns

### 7.1 Pitfall 1: Artificially Inflating Float (Dangling Logic)
* **The Anti-Pattern:** A contractor removes successor relationships from non-critical civil activities so they show 120 days of float.
* **Why it Breaks Systems:** The activities appear low risk. When field delays occur, they do not trigger alarms. Once the delay exceeds 120 days, it abruptly turns critical with zero warning, shocking the project delivery team.
* **The Rule:** Enforce DCMA Point 1 (< 5% missing logic). Every activity must have at least one valid successor.

### 7.2 Pitfall 2: Using As-Planned vs. As-Built for Complex Claims
* **The Anti-Pattern:** A claims lawyer overlays the baseline Gantt chart against the final as-built Gantt chart and claims 45 days for every task that finished late.
* **Why it Breaks Systems:** As-Planned vs. As-Built is static. It ignores the fact that the critical path dynamically shifted three times during the project due to contractor productivity failures. Arbitral tribunals reject static comparisons.
* **The Rule:** Always use contemporaneous Time Impact Analysis (TIA) supported by progress update schedules.
