## 🧠 Section A: Conceptual & Architectural Principles

### Question 1: Evolution of P6 Integration Architectures
1. Compare the four primary P6 integration mechanisms (**P6 Integration API**, **P6 Web Services**, **P6 EPPM REST API**, and **Primavera Gateway**) across:
   - Communication protocol and serialization format;
   - Client runtime prerequisites (e.g. Java JRE vs. zero-dependency HTTP);
   - Suitability for a modern Go + Next.js web application.
2. Why is the legacy P6 Integration API (Java RMI/JNI) difficult to deploy inside containerized Kubernetes environments?
3. Under what enterprise scale and budget conditions is purchasing Primavera Gateway justified over building custom REST/Kafka integration microservices?

### Question 2: Session Leasing and WebLogic Resource Contention
A Go scheduling synchronization daemon runs as a cron job every 5 minutes to extract progress updates from P6 EPPM.
1. Describe the exact authentication handshake of the P6 REST API (`/p6ws/restapi/login` and `JSESSIONID` cookies).
2. If the Go daemon creates a new HTTP client, sends credentials to `/login`, fetches data, and terminates without invoking `/logout`, what happens to the WebLogic application server and P6 concurrent user licensing pool?
3. Design a long-lived Go worker pool pattern that leases a single session, performs periodic heartbeat health checks, and refreshes tokens without exhausting enterprise licenses.

### Question 3: Bidirectional SAP PS ↔ P6 Synchronization Architecture
In the Surya 100MW Solar IPP project, Surya Infra integrates SAP S/4HANA (Project Systems) with Primavera P6 EPPM.
1. Define the Single Source of Truth (SSOT) matrix for the following data elements:
   - WBS hierarchy structure
   - Approved Budget at Completion ($BAC$)
   - Activity Precedence Relationships (FS, SS, FF, SF)
   - Actual Cost ($AC$)
   - Physical % Complete
   - Target Commercial Operation Date (COD)
2. Explain the operational risk of allowing "two-way synchronization" on schedule dates (e.g. allowing both SAP and P6 users to modify milestone finish dates).
3. How should the integration service handle the structural impedance mismatch between SAP's financial WBS (typically 3–4 levels deep) and P6's operational CPM schedule (frequently containing 3,000+ detailed activities)?

### Question 4: Handling Webhook Notifications at Scale
1. Explain how P6 EPPM Eventing (Webhooks / JMS) notifies external systems of schedule mutations (e.g., activity completion or baseline publication).
2. Why must a webhook receiver service immediately respond with `202 Accepted` or `200 OK` rather than executing CPM forward/backward passes or SAP sync routines synchronously?
3. What mechanism should be implemented to prevent duplicate processing if P6 retries a webhook due to a network glitch?

   `func DoWithRetry(ctx context.Context, client *http.Client, req *http.Request, maxRetries int) (*http.Response, error)`
