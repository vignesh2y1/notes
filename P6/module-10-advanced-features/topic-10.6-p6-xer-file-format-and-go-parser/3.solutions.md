## 🧠 Section A: Conceptual & Format Specification Principles

### Solution 1: Grammatical Anatomy of the .XER Format

#### 1. Five Fundamental Markers
1. **`ERMHDR` (Line 1):** The mandatory enterprise header. Format: `ERMHDR\t<version>\t<export_date>\t<user_info>`. Identifies the file as an authentic Primavera export and specifies the database schema version.
2. **`%T` (Table Marker):** Indicates the start of a relational table section (e.g. `%T\tTASK`). Resets active column definitions.
3. **`%F` (Field Header):** Immediately follows `%T`. Defines the ordered list of column names for that table separated by tabs (e.g. `%F\ttask_id\ttask_code\ttask_name`).
4. **`%R` (Record Row):** Follows `%F`. Contains tab-delimited values corresponding exactly to the `%F` columns.
5. **`%E` (End of File):** The final line of the document. Confirms the export was not truncated or interrupted.

#### 2. Multiple `%T` Blocks for the Same Table
Yes, a `.XER` file can contain multiple `%T` blocks for the same table name (for instance, when exporting multiple projects in a single batch, or when P6 flushes project data in chunks).
* **Parser Handling:** The parser must **not** overwrite previous records. It must simply append new records to the existing table slice or map, re-parsing the `%F` header in case column ordering differs slightly across blocks.

#### 3. Predicate Relationship Types in `TASKPRED`
* `PR_FS`: **Finish-to-Start** (Successor Early Start $\ge$ Predecessor Early Finish + Lag).
* `PR_SS`: **Start-to-Start** (Successor Early Start $\ge$ Predecessor Early Start + Lag).
* `PR_FF`: **Finish-to-Finish** (Successor Early Finish $\ge$ Predecessor Early Finish + Lag).
* `PR_SF`: **Start-to-Finish** (Successor Early Finish $\ge$ Predecessor Early Start + Lag).

### Solution 2: Memory & GC Overhead in Naive Go Parsers

#### 1. Heap Allocation Calculation for Naive Parser
For a 50MB file with 1,200,000 lines and 20 columns per line:
1. `strings.Split(entireFile, "\n")`:
   - Allocates 1 massive slice of 1,200,000 strings.
   - Generates 1,200,000 substring allocations $\approx$ **1.2 Million objects**.
2. Iterating through lines and calling `strings.Split(line, "\t")`:
   - For each line: allocates 1 slice of 20 strings + 20 individual string objects = 21 allocations per line.
   - Total allocations: $1,200,000 \times 21 = \mathbf{25,200,000\text{ heap allocations}}$!
   - Total memory churn: Over **1.2 GB of heap memory** allocated and immediately discarded.

#### 2. Impact on Go Runtime & Garbage Collector
* **Stop-the-World (STW) & Mark-and-Sweep:** Go's concurrent garbage collector must scan all 25.2 million pointers. GC cycles run continuously, consuming 80%+ of CPU cycles.
* **L1/L2 Cache Eviction:** Constant pointer allocations pollute CPU caches, resulting in memory latency spikes.
* **Throughput Degradation:** Total parse time balloons from ~180ms to over **4.5–6.0 seconds**.

#### 3. How Streaming `bufio.Reader` Eliminates Overhead
* Reads file in contiguous 64KB blocks, reusing a single fixed-size byte buffer.
* Lines are evaluated as raw byte slices (`[]byte`) referencing the read buffer directly.
* Token splitting uses byte index scanning without converting tokens to Go `string` objects unless they are actively stored in the final domain model.
* Heap allocations drop by **96%**, and GC pauses become negligible.

### Solution 3: Character Encoding and Internationalization

#### 1. Why UTF-8 Ingestion Fails on Legacy Exports
Primavera P6 Professional running on Windows desktops historically exported .XER files using the Windows ANSI code page of the host OS—typically **Windows-1252 (CP1252)** in North America and Western Europe.
* Characters such as accented vowels (`é`, `à`, `ü`), smart quotes (`“`, `”`), and currency symbols (`€`, `£`) are represented as single bytes with values $> 127$ in Windows-1252.
* When a Go parser decodes these as UTF-8, the runtime encounters invalid multi-byte sequence headers and returns `utf8.RuneError` or corrupted replacement characters (`\uFFFD`).

#### 2. Automatic Detection & Transcoding in Go
```go
package xer

import (
	"bytes"
	"io"
	"golang.org/x/text/encoding/charmap"
	"golang.org/x/text/transform"
)

// WrapEncodingReader detects if input is Windows-1252 and returns a UTF-8 transcode reader.
func WrapEncodingReader(r io.Reader) (io.Reader, error) {
	headerBuf := make([]byte, 512)
	n, err := io.ReadFull(r, headerBuf)
	if err != nil && err != io.ErrUnexpectedEOF {
		return nil, err
	}

	combined := io.MultiReader(bytes.NewReader(headerBuf[:n]), r)

	// Check if header or data contains high ASCII bytes not valid in UTF-8
	// If detected, transcode via Windows-1252 decoder:
	decoder := charmap.Windows1252.NewDecoder()
	return transform.NewReader(combined, decoder), nil
}
```

#### 3. Multiline Text Fields
In `.XER`, if a memo or notebook topic contains newlines, P6 encodes them as `\r\n` or escapes them, but sometimes raw newlines appear between tabs.
* A robust parser tracks whether the number of extracted tokens matches `len(currentFields)`.
* If a line has fewer columns, it buffers the line and reads the next line, appending it as a multiline continuation until the required column count is satisfied.

### Solution 4: Relational Foreign Key Graph Assembly

#### 1. Relational Links
```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                            .XER RELATIONAL SCHEMA GRAPH                                          │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│   [PROJECT] (proj_id)                                                                            │
│       │                                                                                          │
│       ├──(1:N)──> [PROJWBS] (wbs_id, proj_id, parent_wbs_id)                                     │
│       │                 │                                                                        │
│       │                 └──(1:N)──> [TASK] (task_id, proj_id, wbs_id)                            │
│       │                                 │                   │                                    │
│       │                                 ├──(1:N)            └──(1:N)                             │
│       │                                 ▼                   ▼                                    │
│       └─────────────────────────> [TASKPRED]            [TASKRSRC] <──(N:1)── [RSRC] (rsrc_id)   │
│                                   (pred_task_id,        (task_id,                                │
│                                    task_id)              rsrc_id)                                │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 2. Why `TASKPRED` Must Wait for `TASK`
`TASKPRED` contains foreign keys `pred_task_id` and `task_id`.
* The `.XER` file may emit `TASKPRED` records before all activities in `TASK` are parsed.
* Even if `TASK` appears earlier in the file, relationships reference activities across different WBS branches and sub-projects.
* Attempting to wire memory pointers during the streaming pass of `TASKPRED` risks referencing un-instantiated activities.
* **The Rule:** Ingest all tables into indexed primary-key lookup maps first (`map[int]*Activity`), and perform edge pointer assembly in a dedicated **post-parse graph assembly step**.

### Solution 6: Defending Against the "Trailing Tab" Anomaly

#### 1. Length of `strings.Split(Row 2, "\t")`
- Row 2: `%R\t502\t101\tACT-02\tPiling\tTK_NotStart\t120.0`
- Count of tokens: `["%R", "502", "101", "ACT-02", "Piling", "TK_NotStart", "120.0"]`
- Resulting slice length: **7**.
- But `%F` has 10 columns! Trying to read `tokens[8]` or `tokens[9]` immediately crashes with:
  `panic: runtime error: index out of range [8] with length 7`.

#### 2. Defensive Bounds-Checking Routine in Go
```go
package xer

type RecordAccessor struct {
	tokens   [][]byte
	fieldMap map[string]int
}

func NewRecordAccessor(tokens [][]byte, fieldMap map[string]int) *RecordAccessor {
	return &RecordAccessor{tokens: tokens, fieldMap: fieldMap}
}

// GetString safely returns the string value or empty string if missing/out of bounds.
func (ra *RecordAccessor) GetString(fieldName string) string {
	idx, exists := ra.fieldMap[fieldName]
	if !exists || idx >= len(ra.tokens) {
		return ""
	}
	return string(ra.tokens[idx])
}

// GetFloat64 safely parses float or returns fallback.
func (ra *RecordAccessor) GetFloat64(fieldName string, fallback float64) float64 {
	s := ra.GetString(fieldName)
	if s == "" {
		return fallback
	}
	val, err := strconv.ParseFloat(s, 64)
	if err != nil {
		return fallback
	}
	return val
}
```

### Solution 7: Calendar Decoding in the `CALENDAR` Table

#### 1. Columns of `CALENDAR`
* `clndr_id`: Primary key ID
* `default_flag`: `Y` or `N`
* `clndr_name`: Name (e.g. `Standard 5 Day Workweek`, `Solar 7 Day Site Calendar`)
* `clndr_type`: `CA_Base` (Global), `CA_Project` (Project-specific), `CA_Rsrc` (Resource)
* `clndr_data`: Binary/encoded string specifying the work pattern and exceptions

#### 2. Anatomy of `clndr_data`
In P6, `clndr_data` defines:
1. **Standard Weekly Work Pattern:** Shifts for Sunday through Saturday (e.g. `08:00-12:00, 13:00-17:00` for Monday–Friday, `0` hours for Saturday/Sunday).
2. **Exception Days (Holidays):** Specific dates where standard working hours are overridden to 0 (e.g. `2026-08-15` Indian Independence Day).
3. **Special Working Days:** Weekend dates designated as working makeup days.

#### 3. Why Calendar Parsing is Mandatory Prior to CPM Scheduling
CPM durations in P6 are denominated in **working hours**, not elapsed calendar hours:
* An activity with a duration of 80 hours takes 10 calendar days on an 8-hour/day 7-day calendar, but **14 calendar days** on a 5-day Monday–Friday calendar!
* Calculating Early and Late dates without the parsed calendar produces incorrect dates that can misstate contractual milestones by weeks.

## 💻 Section C: Engine Architecture & Golang Implementation

### Solution 8: High-Performance Zero-Allocation Byte Tokenizer

```go
package xer

import (
	"bytes"
)

// FastTokenizeTabs splits a byte slice on tabs without heap allocations.
func FastTokenizeTabs(line []byte, dest [][]byte) [][]byte {
	dest = dest[:0]
	start := 0

	for {
		idx := bytes.IndexByte(line[start:], '\t')
		if idx == -1 {
			dest = append(dest, line[start:])
			break
		}
		dest = append(dest, line[start:start+idx])
		start += idx + 1
	}

	return dest
}
```

### Solution 9: Streaming Table State Machine in Go

```go
package xer

import (
	"bytes"
	"fmt"
)

type ParserState int

const (
	StateAwaitHeader ParserState = iota
	StateReadingTable
	StateReadingFields
	StateReadingRecords
	StateEOF
)

type XERStateMachine struct {
	state          ParserState
	activeTable    string
	isCoreTable    bool
	fieldNames     []string
	fieldMap       map[string]int
	scratchTokens  [][]byte
}

func NewXERStateMachine() *XERStateMachine {
	return &XERStateMachine{
		state:         StateAwaitHeader,
		fieldMap:      make(map[string]int),
		scratchTokens: make([][]byte, 0, 100),
	}
}

// ProcessLine processes a single line and transitions state.
func (sm *XERStateMachine) ProcessLine(line []byte) error {
	if len(line) == 0 {
		return nil
	}

	switch {
	case bytes.HasPrefix(line, []byte("ERMHDR")):
		sm.state = StateReadingTable
		return nil

	case bytes.Equal(line, []byte("%E")):
		sm.state = StateEOF
		return nil

	case bytes.HasPrefix(line, []byte("%T\t")):
		sm.activeTable = string(bytes.TrimPrefix(line, []byte("%T\t")))
		// Core table verification
		switch sm.activeTable {
		case "PROJECT", "PROJWBS", "TASK", "TASKPRED", "RSRC", "TASKRSRC", "CALENDAR":
			sm.isCoreTable = true
		default:
			sm.isCoreTable = false // Skip non-essential metadata tables
		}
		sm.state = StateReadingFields
		return nil

	case bytes.HasPrefix(line, []byte("%F\t")):
		if !sm.isCoreTable {
			return nil
		}
		raw := bytes.TrimPrefix(line, []byte("%F\t"))
		tokens := bytes.Split(raw, []byte("\t"))
		sm.fieldMap = make(map[string]int, len(tokens))
		for i, tok := range tokens {
			sm.fieldMap[string(tok)] = i
		}
		sm.state = StateReadingRecords
		return nil

	case bytes.HasPrefix(line, []byte("%R\t")):
		if !sm.isCoreTable {
			return nil // Zero parsing cost for non-core tables
		}
		raw := bytes.TrimPrefix(line, []byte("%R\t"))
		sm.scratchTokens = FastTokenizeTabs(raw, sm.scratchTokens)
		// Dispatch to domain model...
		return nil
	}

	return nil
}
```

### Solution 10: Complete CPM Graph Construction and Cycle Verification

```go
package xer

import (
	"errors"
	"fmt"
)

// BuildCPMGraph constructs the executable CPM DAG from parsed .XER tables.
func BuildCPMGraph(parsed *ParsedSchedule) (*NetworkEngine, error) {
	opts := ScheduleOptions{
		DataDate: parsed.Projects[101].DataDate,
	}
	engine := NewNetworkEngine(opts)

	// 1. Register all activities
	for _, a := range parsed.Activities {
		act := &Activity{
			ID:                     fmt.Sprintf("%d", a.ID),
			Code:                   a.Code,
			Name:                   a.Name,
			DurationHours:          int(a.OriginalDuration),
			RemainingDurationHours: int(a.RemainingDuration),
			ActualStart:            a.ActualStart,
			ActualFinish:           a.ActualFinish,
			PrimaryConstraint:      ConstraintType(a.PrimaryConstraint),
			PrimaryDate:            a.ConstraintDate,
		}
		engine.AddActivity(act)
	}

	// 2. Connect all relationships
	for _, r := range parsed.Relationships {
		predID := fmt.Sprintf("%d", r.PredecessorID)
		succID := fmt.Sprintf("%d", r.SuccessorID)

		var relType RelationType
		switch r.Type {
		case "PR_FS":
			relType = RelFinishToStart
		case "PR_SS":
			relType = RelStartToStart
		case "PR_FF":
			relType = RelFinishToFinish
		case "PR_SF":
			relType = RelStartToFinish
		default:
			relType = RelFinishToStart
		}

		if err := engine.AddRelationship(predID, succID, relType, int(r.LagHours)); err != nil {
			// Predecessor or successor missing (e.g. cross-project relationship)
			continue
		}
	}

	// 3. Cycle Detection via Kahn's Algorithm
	topoOrder, err := engine.topologicalSort()
	if err != nil {
		// Detect exact cycle path using Depth-First Search (DFS)
		cyclePath := engine.findCycleDFS()
		return nil, fmt.Errorf("XER network contains circular dependency loop: %s", cyclePath)
	}

	// 4. Execute CPM pass
	if err := engine.Solve(); err != nil {
		return nil, fmt.Errorf("CPM schedule calculation failed: %w", err)
	}

	return engine, nil
}
```
