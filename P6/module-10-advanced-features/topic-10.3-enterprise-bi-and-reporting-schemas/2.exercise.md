## 🧠 Section A: Conceptual & Architectural Principles

### Question 1: OLTP 3NF vs. OLAP Dimensional Warehousing
1. Explain why the native operational schema of Oracle Primavera P6 (e.g., `TASK`, `TASKPRED`, `PROJWBS`, `TASKRSRC`) is poorly suited for serving executive portfolio dashboards in Next.js.
2. In P6, how are time-phased cost curves (Planned Value S-Curves) stored in the database versus how they are presented in the user interface?
3. What is the fundamental difference between the grain of an operational transaction in P6 and the grain of an analytical record in `fact_daily_activity_snapshot`?

### Question 2: Star Schema Design & WBS Hierarchy Flattening
An enterprise portfolio contains 250 projects, each with a hierarchical WBS tree up to 7 levels deep.
1. Why does querying a normalized WBS table using recursive Common Table Expressions (`WITH RECURSIVE`) degrade under high dashboard concurrency?
2. Design the schema for table `dim_wbs` using the **flattened dimension pattern**. How does this pattern allow a BI user in Power BI or Looker to filter by "Phase" or "Subsystem" with a simple `WHERE` clause without recursive joins?
3. Under what conditions should a Snowflake schema be preferred over a Star schema in scheduling analytics, and why do modern analytical engines strongly favor the Star schema?

### Question 3: Slowly Changing Dimensions (SCD Type 2) in Project Controls
During month 4 of the Surya 100MW Solar project, the owner approves a formal Scope Change (Baseline Revision B01) increasing the Budgeted Cost of `ACT-STR` (Tracker Mounting) from ₹15,000,000 to ₹22,000,000 and extending its duration from 30 days to 45 days.
1. If the data warehouse used **SCD Type 1** (in-place row overwrite), what would happen to the audited Earned Value ($EV$) and Planned Value ($PV$) figures for months 1, 2, and 3?
2. Detail the exact row mutations required in an **SCD Type 2** `dim_activity` table when this change occurs.
3. How does the surrogate primary key (`activity_key`) ensure that past daily snapshot fact records preserve their historical financial integrity?

### Question 4: Row-Oriented (PostgreSQL) vs. Columnar (ClickHouse) Storage
A portfolio with 50,000 activities tracked daily over a 3-year EPC project generates approximately 54.7 million snapshot rows.
1. Explain how a row-oriented relational database (such as standard PostgreSQL) executes a query calculating the monthly sum of Earned Value across all projects:
   `SELECT snapshot_date, SUM(ev_cumulative) FROM fact_daily_activity_snapshot GROUP BY snapshot_date;`
2. Explain how a columnar database (such as ClickHouse) executes this identical query using vectorized SIMD instructions.
3. Why does columnar compression (e.g., Gorilla, DoubleDelta, ZSTD) achieve compression ratios exceeding 85% on schedule snapshot tables?
