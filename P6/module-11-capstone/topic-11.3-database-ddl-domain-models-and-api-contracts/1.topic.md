# Topic 11.3: Database DDL, Domain Models & API Contracts

## 1. Executive Summary & Plain-English Analogy

### 1.1 The Enterprise Ledger: Modernizing the P6 Database Schema
Oracle Primavera P6's underlying relational database schema contains over 160 tables, developed across three decades. It carries significant legacy baggage: 8-character column names from the 1990s (`task_id`, `clndr_id`, `rsrc_id`), stored procedures with thousands of lines of procedural SQL, and non-standard hierarchical traversal tricks.

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                   P6 LEGACY SCHEMA vs. MODERN POSTGRESQL 16 / GO ARCHITECTURE                    │
├───────────────────────────────────┬──────────────────────────────────────────────────────────────┤
│ Oracle Primavera P6 Legacy Schema │ Modern PostgreSQL 16 + Go Domain Engine                      │
├───────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ * 160+ tables with arcane names.  │ * 17 normalized, clean, strongly-typed domain tables.        │
│ * Stored procedures run CPM logic.│ * In-memory Go engine executes CPM; DB handles persistence.  │
│ * Recursive integer parent IDs.   │ * Native `ltree` extension with sub-millisecond GiST indexes.│
│ * Pessimistic row locking crashes.│ * Optimistic Concurrency Control (OCC) via `revision_id`.    │
│ * Heavy SOAP / XML Web Services.  │ * High-throughput gRPC (Protobuf) + OpenAPI 3.1 REST API.    │
└───────────────────────────────────┴──────────────────────────────────────────────────────────────┘
```

When building a modern project controls engine in Golang and Next.js, we do not reproduce P6's legacy clutter. Instead, we extract its **core mathematical and relational invariants** into an elegant, high-throughput PostgreSQL 16 schema. The database acts as a **durable ACID transactional store**, while the Go service layer handles graph simulation and discrete-event calculations in memory.

## 2. Production-Ready PostgreSQL 16 DDL Migration

Below is the complete, production-grade SQL migration defining all 17 essential tables, complete with foreign keys, constraints, triggers, and composite traversal indexes:

```sql
-- Migration: 001_create_project_controls_schema.sql
-- Description: Complete 17-table schema for high-concurrency P6-grade scheduling engine.

CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "ltree";

-- ============================================================================
-- 1. ORGANIZATIONAL BREAKDOWN STRUCTURE (OBS)
-- ============================================================================
CREATE TABLE obs_nodes (
    obs_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    obs_code VARCHAR(32) NOT NULL UNIQUE,
    obs_name VARCHAR(255) NOT NULL,
    parent_obs_id UUID REFERENCES obs_nodes(obs_id) ON DELETE RESTRICT,
    node_path ltree NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
);
CREATE INDEX idx_obs_nodes_path ON obs_nodes USING GIST (node_path);
CREATE INDEX idx_obs_nodes_parent ON obs_nodes(parent_obs_id);

-- ============================================================================
-- 2. ENTERPRISE PROJECT STRUCTURE (EPS)
-- ============================================================================
CREATE TABLE eps_nodes (
    eps_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    eps_code VARCHAR(32) NOT NULL UNIQUE,
    eps_name VARCHAR(255) NOT NULL,
    parent_eps_id UUID REFERENCES eps_nodes(eps_id) ON DELETE RESTRICT,
    node_path ltree NOT NULL,
    obs_id UUID NOT NULL REFERENCES obs_nodes(obs_id) ON DELETE RESTRICT,
    default_currency VARCHAR(3) NOT NULL DEFAULT 'INR',
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
);
CREATE INDEX idx_eps_nodes_path ON eps_nodes USING GIST (node_path);
CREATE INDEX idx_eps_nodes_parent ON eps_nodes(parent_eps_id);

-- ============================================================================
-- 3. CALENDARS & EXCEPTIONS
-- ============================================================================
CREATE TABLE calendars (
    calendar_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    calendar_code VARCHAR(64) NOT NULL UNIQUE,
    calendar_name VARCHAR(255) NOT NULL,
    is_global BOOLEAN NOT NULL DEFAULT FALSE,
    hours_per_day NUMERIC(4, 2) NOT NULL DEFAULT 8.00,
    hours_per_week NUMERIC(5, 2) NOT NULL DEFAULT 40.00,
    work_week_mask BIT(7) NOT NULL DEFAULT B'0111110', -- Mon-Fri active (bit 1=Mon, bit 7=Sun)
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
);

CREATE TABLE calendar_exceptions (
    exception_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    calendar_id UUID NOT NULL REFERENCES calendars(calendar_id) ON DELETE CASCADE,
    exception_date DATE NOT NULL,
    is_working_day BOOLEAN NOT NULL DEFAULT FALSE,
    work_hours NUMERIC(4, 2) NOT NULL DEFAULT 0.00,
    reason VARCHAR(255),
    UNIQUE(calendar_id, exception_date)
);
CREATE INDEX idx_cal_exceptions_date ON calendar_exceptions(calendar_id, exception_date);

-- ============================================================================
-- 4. PROJECTS
-- ============================================================================
CREATE TABLE projects (
    project_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_code VARCHAR(64) NOT NULL UNIQUE,
    project_name VARCHAR(255) NOT NULL,
    eps_id UUID NOT NULL REFERENCES eps_nodes(eps_id) ON DELETE RESTRICT,
    obs_id UUID NOT NULL REFERENCES obs_nodes(obs_id) ON DELETE RESTRICT,
    calendar_id UUID NOT NULL REFERENCES calendars(calendar_id) ON DELETE RESTRICT,
    status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE' 
        CHECK (status IN ('PLANNED', 'ACTIVE', 'INACTIVE', 'WHAT_IF', 'ARCHIVED')),
    data_date TIMESTAMPTZ NOT NULL,
    planned_start_date TIMESTAMPTZ NOT NULL,
    must_finish_by_date TIMESTAMPTZ,
    actual_start_date TIMESTAMPTZ,
    actual_finish_date TIMESTAMPTZ,
    revision_id BIGINT NOT NULL DEFAULT 1,
    budget_at_completion NUMERIC(16, 2) NOT NULL DEFAULT 0.00,
    currency VARCHAR(3) NOT NULL DEFAULT 'INR',
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
);
CREATE INDEX idx_projects_eps ON projects(eps_id);
CREATE INDEX idx_projects_status ON projects(status);

-- ============================================================================
-- 5. WORK BREAKDOWN STRUCTURE (WBS)
-- ============================================================================
CREATE TABLE wbs_nodes (
    wbs_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    wbs_code VARCHAR(64) NOT NULL,
    wbs_name VARCHAR(255) NOT NULL,
    parent_wbs_id UUID REFERENCES wbs_nodes(wbs_id) ON DELETE CASCADE,
    node_path ltree NOT NULL,
    obs_id UUID NOT NULL REFERENCES obs_nodes(obs_id) ON DELETE RESTRICT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    UNIQUE(project_id, wbs_code)
);
CREATE INDEX idx_wbs_nodes_path ON wbs_nodes USING GIST (node_path);
CREATE INDEX idx_wbs_project ON wbs_nodes(project_id);

-- ============================================================================
-- 6. ACTIVITIES
-- ============================================================================
CREATE TABLE activities (
    activity_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    wbs_id UUID NOT NULL REFERENCES wbs_nodes(wbs_id) ON DELETE RESTRICT,
    calendar_id UUID NOT NULL REFERENCES calendars(calendar_id) ON DELETE RESTRICT,
    activity_code VARCHAR(32) NOT NULL,
    activity_name VARCHAR(255) NOT NULL,
    activity_type VARCHAR(32) NOT NULL DEFAULT 'TASK_DEPENDENT'
        CHECK (activity_type IN ('TASK_DEPENDENT', 'RESOURCE_DEPENDENT', 'START_MILESTONE', 'FINISH_MILESTONE', 'LEVEL_OF_EFFORT')),
    
    -- Durations (Stored in Working Minutes)
    original_duration BIGINT NOT NULL DEFAULT 0,
    remaining_duration BIGINT NOT NULL DEFAULT 0,
    actual_duration BIGINT NOT NULL DEFAULT 0,
    percent_complete NUMERIC(5, 2) NOT NULL DEFAULT 0.00 CHECK (percent_complete BETWEEN 0 AND 100),
    
    -- Early and Late Dates (Computed by CPM Engine)
    early_start TIMESTAMPTZ,
    early_finish TIMESTAMPTZ,
    late_start TIMESTAMPTZ,
    late_finish TIMESTAMPTZ,
    actual_start TIMESTAMPTZ,
    actual_finish TIMESTAMPTZ,
    
    -- Float Values (Stored in Minutes)
    total_float BIGINT NOT NULL DEFAULT 0,
    free_float BIGINT NOT NULL DEFAULT 0,
    is_critical BOOLEAN NOT NULL DEFAULT FALSE,
    
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    UNIQUE(project_id, activity_code)
);
CREATE INDEX idx_activities_project ON activities(project_id);
CREATE INDEX idx_activities_wbs ON activities(wbs_id);
CREATE INDEX idx_activities_critical ON activities(project_id, is_critical) WHERE is_critical = TRUE;

-- ============================================================================
-- 7. RELATIONSHIPS (DEPENDENCY EDGES)
-- ============================================================================
CREATE TABLE relationships (
    relationship_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    predecessor_id UUID NOT NULL REFERENCES activities(activity_id) ON DELETE CASCADE,
    successor_id UUID NOT NULL REFERENCES activities(activity_id) ON DELETE CASCADE,
    type VARCHAR(2) NOT NULL DEFAULT 'FS' CHECK (type IN ('FS', 'SS', 'FF', 'SF')),
    lag_minutes BIGINT NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    UNIQUE(predecessor_id, successor_id),
    CHECK (predecessor_id != successor_id)
);
CREATE INDEX idx_rel_predecessor ON relationships(predecessor_id);
CREATE INDEX idx_rel_successor ON relationships(successor_id);
CREATE INDEX idx_rel_project ON relationships(project_id);

-- ============================================================================
-- 8. ACTIVITY CONSTRAINTS
-- ============================================================================
CREATE TABLE activity_constraints (
    constraint_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    activity_id UUID NOT NULL REFERENCES activities(activity_id) ON DELETE CASCADE,
    constraint_type VARCHAR(32) NOT NULL
        CHECK (constraint_type IN ('MANDATORY_START', 'MANDATORY_FINISH', 'START_ON_OR_AFTER', 'FINISH_ON_OR_BEFORE', 'AS_LATE_AS_POSSIBLE')),
    constraint_date TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
);
CREATE INDEX idx_act_constraints ON activity_constraints(activity_id);

-- ============================================================================
-- 9. RESOURCES & ASSIGNMENTS
-- ============================================================================
CREATE TABLE resources (
    resource_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    resource_code VARCHAR(32) NOT NULL UNIQUE,
    resource_name VARCHAR(255) NOT NULL,
    resource_type VARCHAR(32) NOT NULL CHECK (resource_type IN ('LABOR', 'NON_LABOR', 'MATERIAL')),
    unit_of_measure VARCHAR(32),
    standard_rate NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
    max_units_per_day NUMERIC(8, 2) NOT NULL DEFAULT 1.00,
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()
);

CREATE TABLE resource_assignments (
    assignment_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    activity_id UUID NOT NULL REFERENCES activities(activity_id) ON DELETE CASCADE,
    resource_id UUID NOT NULL REFERENCES resources(resource_id) ON DELETE RESTRICT,
    planned_units NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
    actual_units NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
    remaining_units NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
    planned_cost NUMERIC(16, 2) NOT NULL DEFAULT 0.00,
    actual_cost NUMERIC(16, 2) NOT NULL DEFAULT 0.00,
    UNIQUE(activity_id, resource_id)
);
CREATE INDEX idx_res_assign_act ON resource_assignments(activity_id);
CREATE INDEX idx_res_assign_res ON resource_assignments(resource_id);

-- ============================================================================
-- 10. BASELINES & SNAPSHOTS
-- ============================================================================
CREATE TABLE baselines (
    baseline_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    baseline_code VARCHAR(32) NOT NULL,
    baseline_name VARCHAR(255) NOT NULL,
    frozen_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    frozen_by VARCHAR(128) NOT NULL,
    UNIQUE(project_id, baseline_code)
);

CREATE TABLE activity_baselines (
    baseline_id UUID NOT NULL REFERENCES baselines(baseline_id) ON DELETE CASCADE,
    activity_id UUID NOT NULL,
    planned_early_start TIMESTAMPTZ NOT NULL,
    planned_early_finish TIMESTAMPTZ NOT NULL,
    planned_duration BIGINT NOT NULL,
    planned_cost NUMERIC(16, 2) NOT NULL DEFAULT 0.00,
    PRIMARY KEY (baseline_id, activity_id)
);

-- ============================================================================
-- 11. COST ACCOUNTS & EVM SNAPSHOTS
-- ============================================================================
CREATE TABLE cost_accounts (
    cost_account_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    account_code VARCHAR(64) NOT NULL UNIQUE,
    account_name VARCHAR(255) NOT NULL,
    description TEXT
);

CREATE TABLE evm_snapshots (
    snapshot_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    data_date TIMESTAMPTZ NOT NULL,
    budget_at_completion NUMERIC(16, 2) NOT NULL,
    planned_value NUMERIC(16, 2) NOT NULL,

    actual_cost NUMERIC(16, 2) NOT NULL,
    cpi NUMERIC(6, 4) NOT NULL,
    spi NUMERIC(6, 4) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    UNIQUE(project_id, data_date)
);
CREATE INDEX idx_evm_snapshots_proj_date ON evm_snapshots(project_id, data_date);

-- ============================================================================
-- 12. ACTIVITY CODES & ASSIGNMENTS
-- ============================================================================
CREATE TABLE activity_codes (
    code_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code_scope VARCHAR(32) NOT NULL CHECK (code_scope IN ('GLOBAL', 'EPS', 'PROJECT')),
    scope_id UUID, -- NULL if GLOBAL, EPS_ID if EPS, PROJECT_ID if PROJECT

    code_value VARCHAR(64) NOT NULL,
    description VARCHAR(255),

    code_id UUID NOT NULL REFERENCES activity_codes(code_id) ON DELETE CASCADE,
```

## 4. API Contracts: gRPC Service Definitions (Protobuf)

Below is the production gRPC Protobuf specification (`scheduling_v1.proto`) providing sub-10ms binary communication between services:

```protobuf
syntax = "proto3";

package scheduling.v1;

option go_package = "github.com/surya/p6/gen/v1;schedulingv1";

import "google/protobuf/timestamp.proto";

service SchedulingEngineService {
  // Recalculates CPM Early/Late dates and Floats for a given project network
  rpc RecalculateSchedule(RecalculateScheduleRequest) returns (RecalculateScheduleResponse);

  // Runs Parallel SGS Resource Leveling across designated resource pools
  rpc LevelResources(LevelResourcesRequest) returns (LevelResourcesResponse);

  // Generates complete EVM trend snapshot metrics for a reporting period
  rpc GenerateEVMSnapshot(GenerateEVMSnapshotRequest) returns (GenerateEVMSnapshotResponse);
}

message RecalculateScheduleRequest {
  string project_id = 1;
  google.protobuf.Timestamp data_date = 2;
  int64 client_revision_id = 3;
}

message RecalculateScheduleResponse {
  string project_id = 1;
  int64 new_revision_id = 2;
  int64 calculation_time_ms = 3;
  google.protobuf.Timestamp project_finish_date = 4;
  int32 total_activities_processed = 5;
  int32 critical_activities_count = 6;
  repeated ActivityScheduleResult updated_activities = 7;
}

message ActivityScheduleResult {
  string activity_id = 1;
  google.protobuf.Timestamp early_start = 2;
  google.protobuf.Timestamp early_finish = 3;
  google.protobuf.Timestamp late_start = 4;
  google.protobuf.Timestamp late_finish = 5;
  int64 total_float_minutes = 6;
  int64 free_float_minutes = 7;
  bool is_critical = 8;
}

message LevelResourcesRequest {
  string project_id = 1;
  repeated string resource_ids = 2;
  bool preserve_must_finish_by = 3;
}

message LevelResourcesResponse {
  string project_id = 1;
  int64 delayed_days = 2;
  int32 resolved_conflicts_count = 3;
}

message GenerateEVMSnapshotRequest {
  string project_id = 1;
  google.protobuf.Timestamp data_date = 2;
}

message GenerateEVMSnapshotResponse {
  string project_id = 1;
  double budget_at_completion = 2;
  double planned_value = 3;
  double earned_value = 4;
  double actual_cost = 5;
  double cpi = 6;
  double spi = 7;
}
```

## 6. Common Pitfalls & High-Performance Database Gotchas

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                      DATABASE ARCHITECTURAL PITFALLS IN SCHEDULING ENGINES                       │
├───────────────────────────────┬───────────────────────────────┬──────────────────────────────────┤
│ Architectural Pitfall         │ Performance Damage            │ Production Mitigation            │
├───────────────────────────────┼───────────────────────────────┼──────────────────────────────────┤
│ 1. Missing Composite Indexes  │ Full table scans on 1,000,000 │ Create composite indexes:        │
│    on Relationship Edges      │ edges during CPM load.        │ `(project_id, predecessor_id)`   │
│                               │                               │ and `(successor_id)`.            │
├───────────────────────────────┼───────────────────────────────┼──────────────────────────────────┤
│ 2. Unbounded CASCADE Deletes  │ Deleting a project locks DB   │ Run soft deletes with background │
│    on 100,000 Activities      │ for 45 seconds under row lock.│ asynchronous purge workers.      │
├───────────────────────────────┼───────────────────────────────┼──────────────────────────────────┤
│ 3. Float Duration Rounding    │ Fractional rounding errors    │ Store ALL durations in integer   │
│    (Float vs BigInt Minutes)  │ cause 1-second float drifts.  │ `BIGINT` working minutes.        │
├───────────────────────────────┼───────────────────────────────┼──────────────────────────────────┤
│ 4. Unindexed JSONB Queries    │ Slow $O(N)$ filter operations │ Store core schedule fields in    │
│    for Activity Dates         │ in Gantt view.                │ typed columns; reserve JSONB for │
│                               │                               │ custom user-defined fields (UDF).│
└───────────────────────────────┴───────────────────────────────┴──────────────────────────────────┘
```

## 7. Summary & Synthesis

The data and contract tier provides the foundational bedrock for the entire platform:
- **Relational Integrity:** 17 normalized PostgreSQL 16 tables model the entire project controls lifecycle with absolute referential integrity.
- **Cache-Aligned Speed:** Composite indices, `ltree` GiST hierarchies, and integer `BIGINT` minute durations guarantee sub-millisecond graph population into Go memory.
- **Interoperability:** Protobuf gRPC contracts deliver high-throughput backend communication, while OpenAPI 3.1 REST contracts provide clean, type-safe Next.js client integration.
