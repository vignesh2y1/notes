### Question 2: Memory Layout & Cache Locality in Golang

- **Approach A (Pointer Graph):**
  ```go
  type ActivityNode struct {
      ID           string
      Predecessors []*ActivityNode
      Successors   []*ActivityNode
  }
  ```
- **Approach B (Contiguous Flat Arena):**
  ```go
  type ActivityNode struct {
      Index                  uint32
      PredecessorEdgeIndices []uint32
      SuccessorEdgeIndices   []uint32
  }
  type GraphArena struct {
      Nodes []ActivityNode
      Edges []RelationshipEdge
  }
  ```
1. Explain how Go's garbage collector (GC) behaves under Approach A versus Approach B when allocating and traversing 100,000 nodes.
2. In terms of CPU hardware cache lines (64 bytes), why does Approach B achieve significantly higher throughput during topological sorting and forward/backward passes?
