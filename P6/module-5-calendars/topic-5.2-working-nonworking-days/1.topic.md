## 1. Executive Summary & The Core Mental Model

### 1.1 The Axiom: Weekly Patterns are Baselines; Reality is Governed by Overrides
In Topic 5.1, we established that a project calendar defines a repeating 7-day cyclical work pattern (e.g., 5-day office, 6-day site civil, 7-day curing).

However, **no industrial project on earth operates on an uninterrupted weekly loop**.
* **Statutory Public Holidays:** Government holidays (Republic Day, Independence Day, Eid, Diwali) shut down sites and engineering offices.
* **Severe Climatic Conditions:** In the Thar Desert of Rajasthan, extreme ambient temperatures exceeding 48°C trigger mandatory governmental curfews prohibiting outdoor manual labor between 12:00 PM and 3:00 PM during May and June.
* **Monsoon Rain Shutdowns:** Flash rains turn desert bentonite clay into impassable mud, halting deep trenching and foundation excavation for days, even while indoor substation wiring continues uninterrupted.
* **Make-Up Days & Accelerated Shifts:** To recover lost time, contractors declare specific Sundays as "Special Working Days" with double-time pay.

## 2. The 3-Tier Hierarchy of Calendar Overrides

When the scheduling engine evaluates whether an arbitrary minute $m$ on calendar date $D$ is working or non-working, it evaluates the hierarchy from highest specificity to lowest:

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                         CALENDAR OVERRIDE RESOLUTION ALGORITHM                                   │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│                                   ┌──────────────────────┐                                       │
│                                   │ Query Date D & Min m │                                       │
│                                   └──────────┬───────────┘                                       │
│                                              │                                                   │
│                                              ▼                                                   │
│                            ┌────────────────────────────────────┐                                │
│                            │ Does a Specific Date Exception     │                                │
│                            │ exist for Calendar C on Date D?    │                                │
│                            └───────┬────────────────────┬───────┘                                │
│                                    │ YES                │ NO                                     │
│                                    ▼                    ▼                                        │
│                 ┌──────────────────────────┐  ┌────────────────────────────────────┐             │
│                 │ Exception Type?          │  │ Query Weekly Pattern for DayOfWeek │             │
│                 ├───┬──────────────────────┤  └───────┬────────────────────┬───────┘             │
│                 │ A │ NON_WORKING -> False │          │ Working Day        │ Non-Working Day     │
│                 │ B │ WORKING -> Use Shifts│          ▼                    ▼                     │
│                 │ C │ MODIFIED -> Shifts   │  ┌────────────────┐   ┌───────────────┐             │
│                 └───┴──────────────────────┘  │ Evaluate Shifts│   │ Return FALSE  │             │
│                                               └────────────────┘   └───────────────┘             │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 The 3 Tiers Defined
1. **Tier 1: Standard Day Template (Baseline):** The default configuration of working hours per day (e.g., 8 hours/day, 40 hours/week) used as a baseline fallback.
2. **Tier 2: Weekly Work Pattern (Cyclical):** Defines the standard recurring 7-day schedule (e.g., Monday–Saturday working, Sunday non-working).
3. **Tier 3: Calendar Exceptions (Specific Date Overrides):**
   * **Type A — Non-Working Exception (Holiday/Shutdown):** A day that would normally be a working day according to the weekly pattern is converted into a zero-work day.
   * **Type B — Working Exception (Make-Up Day):** A day that would normally be non-working (e.g., Sunday) is converted into a working day with specific shifts.
   * **Type C — Modified Hours Exception (Partial Day / Shift Override):** A day whose working shifts are replaced with custom hours (e.g., Half-Day for festival eve or split shifts for desert summer heat).

## 4. Shift Transitions and Cross-Midnight Shifts

In hot climates, high-strength concrete pours for inverter transformer foundations are performed at night. If concrete is poured during the day at 45°C, the water evaporates rapidly, causing catastrophic thermal shrinkage cracking and flash-setting.
Therefore, the contractor introduces a **Night Pouring Shift**:
$$\text{Shift Window: } 21:00 \text{ (Day } N\text{)} \longrightarrow 05:00 \text{ (Day } N+1\text{)}$$

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                              CROSS-MIDNIGHT SHIFT DECOMPOSITION                                  │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│   Day N Timeline (e.g., 14-Oct)                 Day N+1 Timeline (e.g., 15-Oct)                  │
│   00:00                 21:00       24:00       00:00       05:00                       24:00    │
│   ┌───────────────────────┬───────────┐         ┌───────────┬───────────────────────────┐        │
│   │   Non-Working         │ Segment 1 │         │ Segment 2 │        Non-Working        │        │
│   │   (Day Rest)          │ (Night)   │         │ (Dawn)    │        (Day Rest)         │        │
│   │   21.0 hrs            │  3.0 hrs  │         │  5.0 hrs  │        19.0 hrs           │        │
│   └───────────────────────┴───────────┘         └───────────┴───────────────────────────┘        │
│                           ▲           ▲         ▲           ▲                                    │
│                           21:00       24:00     00:00       05:00                                │
│                           └─ Block A ─┘         └── Block B ┘                                    │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### The Midnight Splitting Rule
Because relational database tables and daily calendar patterns are conventionally indexed by calendar date (`date = '2026-10-14'`), any shift crossing midnight is decomposed into two contiguous sub-intervals:
1. **Segment 1 (Day $N$):** `21:00 to 24:00` ($1,260 \text{ to } 1,440 \text{ minutes} = 180 \text{ min}$).
2. **Segment 2 (Day $N+1$):** `00:00 to 05:00` ($0 \text{ to } 300 \text{ minutes} = 300 \text{ min}$).

Total working duration $= 180 + 300 = 480 \text{ minutes} = 8.0 \text{ hours}$.

## 5. Mathematical Date Progression: Forward Walking Algorithm

The core engine operation in any CPM schedule forward pass is:
$$\text{Given Start Timestamp } T_{\text{start}} \text{ and Work Duration } D_{\text{hours}} \implies \text{Compute Finish Timestamp } T_{\text{finish}}$$

### 5.1 The Step-by-Step Forward Walking Algorithm
Let $R$ be the remaining work duration (in minutes), initialized to $D \times 60$.

```text
Step 1: SNAP START TO WORKING TIME
        If T_start falls in a non-working interval (e.g., Sunday or night),
        advance T_start to the very first working minute >= T_start.

Step 2: ZERO DURATION CHECK (MILESTONES)
        If remaining duration R == 0:
            Return T_start (Milestone finishes at the instant it starts).

Step 3: INTERVAL WALKING LOOP
        Set CurrentTime = T_start.
        While R > 0:
            a. Resolve the effective working intervals for CurrentDate = Date(CurrentTime).
            b. For each working interval [I_start, I_end] on CurrentDate:
                i.   If I_end <= CurrentTime: Skip (interval is already in the past).
                ii.  EffectiveStart = max(CurrentTime, I_start).
                iii. AvailableWorkMinutes = I_end - EffectiveStart.
                iv.  If R <= AvailableWorkMinutes:
                         // Remaining work completes inside this interval!
                         T_finish = EffectiveStart + R minutes.
                         Return T_finish.
                v.   Else:
                         // Consume entire interval and continue
                         R = R - AvailableWorkMinutes.
                         CurrentTime = I_end.
            c. Advance CurrentTime to 00:00 of the next calendar day (CurrentDate + 1 day).
```

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                           FORWARD INTERVAL WALKING TRACE                                         │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│  Start Time: Friday 14:00. Remaining Work R = 14 hours (840 minutes).                            │
│  Calendar: 5-Day (08:00 - 12:00, 13:00 - 17:00). Saturday/Sunday Non-Working.                     │
│                                                                                                  │
│  Day 1 (Friday):                                                                                 │
│    • CurrentTime = 14:00.                                                                        │
│    • Interval [13:00, 17:00]: Available = 17:00 - 14:00 = 3 hours (180 min).                     │
│    • R = 840 - 180 = 660 min (11 hours remaining).                                              │
│                                                                                                  │
│  Day 2 (Saturday): Non-working. (0 min consumed, R = 660 min).                                   │
│  Day 3 (Sunday):   Non-working. (0 min consumed, R = 660 min).                                   │
│                                                                                                  │
│  Day 4 (Monday):                                                                                 │
│    • Interval 1 [08:00, 12:00]: Available = 4 hours (240 min).                                   │
│      R = 660 - 240 = 420 min (7 hours remaining).                                                │
│    • Interval 2 [13:00, 17:00]: Available = 4 hours (240 min).                                   │
│      R = 420 - 240 = 180 min (3 hours remaining).                                                │
│                                                                                                  │
│  Day 5 (Tuesday):                                                                                │
│    • Interval 1 [08:00, 12:00]: Available = 4 hours (240 min).                                   │
│    • Since R (180 min) <= Available (240 min):                                                   │
│      T_finish = 08:00 + 180 min = 11:00.                                                         │
│                                                                                                  │
│  Result: T_finish = Tuesday at 11:00.                                                            │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 6. The Inverse Operation: Backward Walking Algorithm

During the CPM **Backward Pass**, the engine computes **Late Dates**.
$$\text{Given Late Finish Timestamp } T_{\text{finish}} \text{ and Duration } D \implies \text{Compute Late Start Timestamp } T_{\text{start}}$$

### 6.1 The Backward Walking Algorithm
The backward walking operation is the mirror symmetric inverse of forward walking:
1. **Snap Finish to Working Time:** If $T_{\text{finish}}$ lands in non-working time, step backward to the latest working minute $\le T_{\text{finish}}$.
2. **Reverse Interval Consumption:** Walk backward through working intervals in reverse chronological order, deducting available working minutes until $R = 0$.

### 6.2 The Round-Trip Reversibility Invariant
A fundamental invariant of any valid scheduling engine is:
$$\text{BackwardWalk}(\text{ForwardWalk}(T, D), D) = T$$
* **Exception Note:** The round-trip invariant holds strictly **if and only if** the original $T$ starts on a valid working minute. If $T$ originally started on a non-working Sunday, the forward walk first snaps to Monday 08:00; walking backward from finish lands on Monday 08:00, not Sunday.

## 7. PostgreSQL Database Schema Extensions for Exceptions

To support arbitrary holidays, weather moratoria, and shift overrides, we extend the database schema from Topic 5.1:

```sql
-- 1. Enum for Exception Types
CREATE TYPE exception_type_enum AS ENUM ('NON_WORKING', 'WORKING', 'MODIFIED_HOURS');

-- 2. Calendar Exceptions Table: Specific single day or date range overrides
CREATE TABLE calendar_exceptions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    calendar_id UUID NOT NULL REFERENCES calendars(id) ON DELETE CASCADE,
    exception_name VARCHAR(150) NOT NULL,
    exception_type exception_type_enum NOT NULL DEFAULT 'NON_WORKING',
    start_date DATE NOT NULL,
    end_date DATE NOT NULL, -- Inclusive end date (start_date = end_date for single day)
    description TEXT,
    
    CONSTRAINT chk_exception_date_order CHECK (end_date >= start_date)
);

CREATE INDEX idx_calendar_exceptions_lookup 
ON calendar_exceptions(calendar_id, start_date, end_date);

-- 3. Exception Shifts Table: Overridden shifts applied when exception_type != 'NON_WORKING'
CREATE TABLE calendar_exception_shifts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    exception_id UUID NOT NULL REFERENCES calendar_exceptions(id) ON DELETE CASCADE,
    shift_index SMALLINT NOT NULL DEFAULT 1,
    start_minute_of_day SMALLINT NOT NULL CHECK (start_minute_of_day BETWEEN 0 AND 1439),
    end_minute_of_day SMALLINT NOT NULL CHECK (end_minute_of_day BETWEEN 1 AND 1440),
    efficiency_factor NUMERIC(3, 2) NOT NULL DEFAULT 1.00,
    
    CONSTRAINT uq_exception_shift_index UNIQUE (exception_id, shift_index),
    CONSTRAINT chk_exception_shift_order CHECK (end_minute_of_day > start_minute_of_day)
);

CREATE INDEX idx_exception_shifts ON calendar_exception_shifts(exception_id);
```

## 8. Production-Grade Golang Calendar Calculator Engine

Below is the complete, high-performance, production-grade Go engine implementing the forward and backward interval walking algorithm with full support for weekly patterns, statutory holidays, and summer split shifts.

```go
package calendar

import (
	"errors"
	"fmt"
	"time"
)

// WorkInterval represents a continuous window of working time on an absolute timeline.
type WorkInterval struct {
	Start time.Time
	End   time.Time
}

// Duration returns the length of the work interval.
func (wi WorkInterval) Duration() time.Duration {
	return wi.End.Sub(wi.Start)
}

// ExceptionType defines the nature of the calendar override.
type ExceptionType string

const (
	ExceptionNonWorking    ExceptionType = "NON_WORKING"
	ExceptionWorking       ExceptionType = "WORKING"
	ExceptionModifiedHours ExceptionType = "MODIFIED_HOURS"
)

// CalendarException represents an override on a specific date or date range.
type CalendarException struct {
	Name          string
	Type          ExceptionType
	StartDate     time.Time // Normalized to 00:00:00 UTC/Location
	EndDate       time.Time // Normalized to 00:00:00 UTC/Location
	Shifts        []Shift   // Used if Type == ExceptionWorking or ExceptionModifiedHours
}

// FullCalendar encapsulates weekly patterns and date exceptions.
type FullCalendar struct {
	ID            string
	Name          string
	Location      *time.Location
	WeeklyPattern [7]DayPattern // Indexed by time.Weekday
	Exceptions    []CalendarException
}

// ResolveDay returns the working shifts for a specific date after applying hierarchy overrides.
func (fc *FullCalendar) ResolveDay(date time.Time) (bool, []Shift) {
	// Normalize to start of day in calendar's location
	normalized := time.Date(date.Year(), date.Month(), date.Day(), 0, 0, 0, 0, fc.Location)

	// Tier 3: Check Exceptions (Highest Priority)
	for _, exc := range fc.Exceptions {
		excStart := time.Date(exc.StartDate.Year(), exc.StartDate.Month(), exc.StartDate.Day(), 0, 0, 0, 0, fc.Location)
		excEnd := time.Date(exc.EndDate.Year(), exc.EndDate.Month(), exc.EndDate.Day(), 0, 0, 0, 0, fc.Location)

		if !normalized.Before(excStart) && !normalized.After(excEnd) {
			if exc.Type == ExceptionNonWorking {
				return false, nil
			}
			return true, exc.Shifts
		}
	}

	// Tier 2: Check Weekly Pattern
	dow := normalized.Weekday()
	pattern := fc.WeeklyPattern[dow]
	if !pattern.IsWorkingDay || len(pattern.Shifts) == 0 {
		return false, nil
	}

	return true, pattern.Shifts
}

// SnapForward snaps a timestamp to the earliest working minute >= t.
func (fc *FullCalendar) SnapForward(t time.Time) time.Time {
	curr := t.In(fc.Location)

	for daysChecked := 0; daysChecked < 365; daysChecked++ {
		isWork, shifts := fc.ResolveDay(curr)
		if isWork {
			curMin := curr.Hour()*60 + curr.Minute()
			for _, s := range shifts {
				if curMin < s.StartMinuteOfDay {
					// Snap to start of shift
					return time.Date(curr.Year(), curr.Month(), curr.Day(),
						s.StartMinuteOfDay/60, s.StartMinuteOfDay%60, 0, 0, fc.Location)
				}
				if curMin >= s.StartMinuteOfDay && curMin < s.EndMinuteOfDay {
					// Already inside a working shift
					return curr.Truncate(time.Minute)
				}
			}
		}

		// Move to beginning of next day
		curr = time.Date(curr.Year(), curr.Month(), curr.Day()+1, 0, 0, 0, 0, fc.Location)
	}

	return t // Fallback
}

// AddWorkingDuration performs the forward interval walking algorithm:
// T_start + D_work -> T_finish
func (fc *FullCalendar) AddWorkingDuration(start time.Time, workDuration time.Duration) (time.Time, error) {
	if workDuration < 0 {
		return time.Time{}, errors.New("work duration cannot be negative")
	}

	// Snap start to next working instant
	curr := fc.SnapForward(start)
	remainingMins := int(workDuration.Minutes())

	if remainingMins == 0 {
		return curr, nil // Milestones complete at start instant
	}

	maxDays := 3650 // Safety bound: 10 years
	for dayCount := 0; dayCount < maxDays && remainingMins > 0; dayCount++ {
		isWork, shifts := fc.ResolveDay(curr)
		if isWork {
			curMinOfDay := curr.Hour()*60 + curr.Minute()

			for _, s := range shifts {
				if s.EndMinuteOfDay <= curMinOfDay {
					continue // Shift already in past
				}

				effectiveStart := s.StartMinuteOfDay
				if curMinOfDay > effectiveStart {
					effectiveStart = curMinOfDay
				}

				availMins := s.EndMinuteOfDay - effectiveStart
				if remainingMins <= availMins {
					finishMin := effectiveStart + remainingMins
					return time.Date(curr.Year(), curr.Month(), curr.Day(),
						finishMin/60, finishMin%60, 0, 0, fc.Location), nil
				}

				// Consume entire available window
				remainingMins -= availMins
				curMinOfDay = s.EndMinuteOfDay
			}
		}

		// Advance to start of next day
		curr = time.Date(curr.Year(), curr.Month(), curr.Day()+1, 0, 0, 0, 0, fc.Location)
	}

	return time.Time{}, errors.New("exceeded maximum calendar horizon during forward walk")
}

// SubtractWorkingDuration performs the backward interval walking algorithm:
// T_finish - D_work -> T_start (Used in CPM Backward Pass for Late Dates)
func (fc *FullCalendar) SubtractWorkingDuration(finish time.Time, workDuration time.Duration) (time.Time, error) {
	if workDuration < 0 {
		return time.Time{}, errors.New("work duration cannot be negative")
	}

	curr := finish.In(fc.Location)
	remainingMins := int(workDuration.Minutes())

	if remainingMins == 0 {
		return curr, nil
	}

	maxDays := 3650
	for dayCount := 0; dayCount < maxDays && remainingMins > 0; dayCount++ {
		isWork, shifts := fc.ResolveDay(curr)
		if isWork {
			curMinOfDay := curr.Hour()*60 + curr.Minute()
			if curr.Hour() == 0 && curr.Minute() == 0 && dayCount > 0 {
				curMinOfDay = MinutesPerDay
			}

			// Iterate shifts backwards
			for i := len(shifts) - 1; i >= 0; i-- {
				s := shifts[i]
				if s.StartMinuteOfDay >= curMinOfDay {
					continue // Shift is in future relative to backward walk
				}

				effectiveEnd := s.EndMinuteOfDay
				if curMinOfDay < effectiveEnd {
					effectiveEnd = curMinOfDay
				}

				availMins := effectiveEnd - s.StartMinuteOfDay
				if remainingMins <= availMins {
					startMin := effectiveEnd - remainingMins
					return time.Date(curr.Year(), curr.Month(), curr.Day(),
						startMin/60, startMin%60, 0, 0, fc.Location), nil
				}

				remainingMins -= availMins
				curMinOfDay = s.StartMinuteOfDay
			}
		}

		// Move backward to end of previous day (23:59:00)
		curr = time.Date(curr.Year(), curr.Month(), curr.Day()-1, 23, 59, 0, 0, fc.Location)
	}

	return time.Time{}, errors.New("exceeded maximum calendar horizon during backward walk")
}
```
