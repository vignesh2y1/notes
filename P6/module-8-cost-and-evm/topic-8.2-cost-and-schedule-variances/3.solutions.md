## 🧠 Section A: Conceptual & Architectural Principles

### Solution 1: The Directionality & Sign Convention of EVM Variances

#### 1. Why $EV$ Appears First in the Subtraction
In standard algebra, a variance is defined as $\text{Observed Result} - \text{Benchmark}$:
* In EVM, the fundamental accomplishment is **Earned Value ($EV$)**—the physical asset delivered to date, valued at baseline rates.
* When evaluating **Cost**, the benchmark is what it cost to deliver that accomplishment ($AC$). Thus: $CV = EV - AC$. If $EV > AC$, you achieved more value than you spent.
* When evaluating **Schedule**, the benchmark is what was planned to be delivered by this point ($PV$). Thus: $SV = EV - PV$. If $EV > PV$, you achieved more value than planned.
* By placing $EV$ first, the mathematical sign naturally aligns with commercial intuition: **Positive is Favorable, Negative is Unfavorable**.

#### 2. Operational Conditions for Cost Variance ($CV$)
* **$CV > 0$ (Under Budget):** Occurs when the team executes work at higher efficiency, lower labor/material unit costs, or with reduced waste compared to baseline assumptions.
* **$CV = 0$ (On Budget):** Occurs when the exact budgeted amount of money was consumed to deliver the certified physical progress.
* **$CV < 0$ (Over Budget):** Occurs when expenditures exceed baseline allocations due to rework, poor labor productivity, expedited freight, or unexpected material price spikes.

#### 3. Interpretation of $SV = -₹10\text{ Crore}$
A negative Schedule Variance of -₹10 Crore means that the physical volume of contractual deliverables completed on site lags behind the approved baseline by a budgeted worth of **₹10,00,00,000**. The contractor has failed to deliver ₹10 Crore worth of planned work.

### Solution 2: The Denominator Dilemma in Variance Percentages

#### 1. Why $CV\%$ Divides by $EV$ and Not $BAC$
* **The Problem with Dividing by $BAC$:**
  Suppose a project has a total budget $BAC = ₹100\text{ Crore}$.
  In Month 1, the contractor completes physical work budgeted at $EV = ₹1\text{ Crore}$, but incurs catastrophic expenses of $AC = ₹3\text{ Crore}$ (a 200% cost overrun!).
  * If calculated against $BAC$:
    $$CV\%_{\text{naive}} = \frac{EV - AC}{BAC} \times 100 = \frac{1 - 3}{100} \times 100 = -2.0\%$$
    Management looks at "-2%" and assumes the project is operating within normal variance tolerances.
  * If calculated against $EV$ (ANSI/EIA-748 Standard):
    $$CV\% = \frac{EV - AC}{EV} \times 100 = \frac{1 - 3}{1} \times 100 = -200.0\%$$
    The metric immediately exposes that the contractor is burning ₹3.00 for every ₹1.00 of asset created.

#### 2. The Division-by-Zero Edge Case ($EV = 0, AC > 0$)
When an activity incurs costs before achieving any physical milestone ($EV = 0$ and $AC > 0$), dividing by $EV$ triggers a division by zero:
* **Engineering Solution:** If $EV == 0$ and $AC > 0$, the backend engine must clamp $CV\%$ to **-100.0%** (representing a complete loss of invested capital with zero delivered asset) or return an explicit `STATUS_COST_WITHOUT_PROGRESS` error code, preventing `NaN` or `+Inf` in JSON payloads.

#### 3. Why $SV\%$ Divides by $PV$
$PV$ represents the cumulative volume of work that was scheduled to be completed up to the Data Date. Dividing by $PV$ answers the question: *"What proportion of our scheduled commitment failed to materialize?"* 
Dividing by $BAC$ would distort early-stage schedule slips because $BAC$ represents the total project end-state.

### Solution 3: The Schedule Variance in Dollars Paradox

#### 1. Metrics at Month 20 (Delayed Finish)
* Approved baseline budget: $BAC = ₹400\text{ Crore}$ scheduled to finish at Month 12.
* At Month 20, all work is finally completed.
* **$PV$ at Month 20:** Because Month 20 is past the baseline finish (Month 12), $PV$ is frozen at $BAC$:
  $$PV = BAC = ₹400\text{ Crore}$$
* **$EV$ at Month 20:** Since 100% of physical scope is completed:
  $$EV = BAC = ₹400\text{ Crore}$$
* **Traditional Schedule Variance ($SV$):**
  $$SV = EV - PV = ₹400\text{ Crore} - ₹400\text{ Crore} = ₹0.00$$

#### 2. The Fundamental Paradox
Even though the project is **8 months late**, traditional currency-based Schedule Variance reports **$SV = ₹0.00$**!
* Because $PV$ ceases to grow after the baseline finish date ($T_{\text{baseline}}$), while $EV$ continues to accumulate until the last task is finished, the difference between them inevitably shrinks to zero.
* As a delayed project limps from Month 12 to Month 20, $SV$ changes from **-₹100 Cr $\to$ -₹50 Cr $\to$ -₹10 Cr $\to$ ₹0 Cr**.
* A naive dashboard tracks this trajectory as a positive trend, suggesting the project is "recovering," when in truth the contractor is merely consuming unauthorized calendar time.

### Solution 4: Conceptual Mechanics of Earned Schedule ($ES$)

#### 1. Difference in Measurement Axes
* **Classical $SV$:** Measures variance along the **Vertical (Cost/Currency) Axis** in Rupees, Dollars, or Hours.
* **Earned Schedule ($SV_t$):** Measures variance along the **Horizontal (Time) Axis** in Months, Weeks, or Days.

#### 2. Formal Definitions
* **$ES$ (Earned Schedule):** The date/time at which the currently earned value ($EV$) was originally scheduled to be achieved along the baseline $PV$ curve.
* **$AT$ (Actual Time):** The actual elapsed duration from project start to the current Data Date.
* **$SV_t$ (Time-Based Schedule Variance):**
  $$SV_t = ES - AT$$
  Measured in calendar units (e.g., -2.4 months).

#### 3. Resolution of the Paradox at Month 20
* **$AT$:** 20.0 months.
* **$ES$:** When was $EV = ₹400\text{ Crore}$ scheduled to occur? At Month 12.0 ($ES = 12.0\text{ months}$).
* **$SV_t$:**
  $$SV_t = ES - AT = 12.0\text{ months} - 20.0\text{ months} = -8.0\text{ months}$$
Unlike traditional $SV$ which falsely reports ₹0, **Earned Schedule correctly reports that the project is 8.0 months late**!

### Solution 5: Evaluation of 220kV Pooling Substation Package

#### 1. Planned Value ($PV$) at Month 5
From the cumulative baseline table:
$$PV_5 = ₹21,60,00,000 \text{ (₹21.60 Crore)}$$

#### 2. Earned Value ($EV$) at Month 5
$$BAC = ₹36,00,00,000 \qquad \text{Physical Progress} = 35.0\%$$
$$EV = ₹36,00,00,000 \times 0.35 = ₹12,60,00,000 \text{ (₹12.60 Crore)}$$

#### 3. Cost Variance ($CV$) and $CV\%$
Given $AC = ₹15,12,00,000$:
$$CV = EV - AC = ₹12,60,00,000 - ₹15,12,00,000 = -₹2,52,00,000 \text{ (-₹2.52 Crore Overrun)}$$
$$CV\% = \left( \frac{CV}{EV} \right) \times 100 = \left( \frac{-2.52}{12.60} \right) \times 100 = -20.0\%$$
* The subcontractor is burning ₹1.20 for every ₹1.00 of asset value delivered.

#### 4. Schedule Variance ($SV$) and $SV\%$
$$SV = EV - PV = ₹12,60,00,000 - ₹21,60,00,000 = -₹9,00,00,000 \text{ (-₹9.00 Crore Behind Schedule)}$$
$$SV\% = \left( \frac{SV}{PV} \right) \times 100 = \left( \frac{-9.00}{21.60} \right) \times 100 = -41.67\%$$
* More than 41% of scheduled work was not delivered.

#### 5. Earned Schedule ($ES$) Interpolation
We locate $EV = ₹12.60\text{ Crore}$ within the cumulative $PV$ series:
* $PV_3 = ₹9.00\text{ Crore}$
* $PV_4 = ₹14.40\text{ Crore}$
Since $PV_3 \le EV < PV_4$, the base period is $C = 3$.

Interpolate fraction $I$:
$$I = \frac{EV - PV_3}{PV_4 - PV_3} = \frac{12.60 - 9.00}{14.40 - 9.00} = \frac{3.60}{5.40} = 0.667\text{ months}$$
$$ES = C + I = 3.0 + 0.667 = 3.667\text{ months}$$

#### 6. Time-Based Schedule Variance ($SV_t$)
Given $AT = 5.0\text{ months}$:
$$SV_t = ES - AT = 3.667 - 5.0 = -1.333\text{ months}$$
In days (at 30 days/month):
$$-1.333 \times 30 = -40\text{ calendar days behind schedule!}$$

### Solution 6: The Inverter Foundation Rebar Overrun

#### 1. Cost Variance ($CV$ and $CV\%$)
* $EV = 16 \times ₹20,00,000 = ₹3,20,00,000$
* $AC = ₹4,48,00,000$
$$CV = EV - AC = ₹3,20,00,000 - ₹4,48,00,000 = -₹1,28,00,000 \text{ (-₹1.28 Crore Overrun)}$$
$$CV\% = \left( \frac{-1.28}{3.20} \right) \times 100 = -40.0\%$$

#### 2. Schedule Variance ($SV$ and $SV\%$)
* $PV = 20 \times ₹20,00,000 = ₹4,00,00,000$
$$SV = EV - PV = ₹3,20,00,000 - ₹4,00,00,000 = -₹80,00,000 \text{ (-₹80 Lakhs)}$$
$$SV\% = \left( \frac{-0.80}{4.00} \right) \times 100 = -20.0\%$$

#### 3. Industrial Interpretation
Marwar Civils is in acute distress on **both dimensions**:
* **Physical delay:** They are 4 foundations (20%) behind schedule.
* **Severe financial bleed:** They are spending ₹1.40 for every ₹1.00 of baseline value (a 40% cost overrun). They have consumed 70% of their total contract budget ($₹4.48\text{Cr} / ₹6.40\text{Cr}$) while completing only 50% of the foundations!

### Solution 7: Reconciling Conflicting Signals (Ahead of Schedule but Over Budget)

#### 1. Variance Calculations
Given $PV = ₹42.0\text{ Cr}, EV = ₹50.4\text{ Cr}, AC = ₹58.8\text{ Cr}$:
$$CV = EV - AC = ₹50.4\text{ Cr} - ₹58.8\text{ Cr} = -₹8.4\text{ Crore}$$
$$CV\% = \left( \frac{-8.4}{50.4} \right) \times 100 = -16.67\% \text{ (Cost Overrun)}$$
$$SV = EV - PV = ₹50.4\text{ Cr} - ₹42.0\text{ Cr} = +₹8.4\text{ Crore}$$
$$SV\% = \left( \frac{+8.4}{42.0} \right) \times 100 = +20.0\% \text{ (Ahead of Schedule)}$$

#### 2. Physical & Economic Explanation
A project can be ahead of schedule while over budget when the management **intentionally "crashes" the schedule** by trading money for time.

#### 3. Real-World Operational Drivers on Surya Solar Site:
1. **Double-Shift Overtime & Night Lighting:** The contractor authorized 24/7 pile-driving shifts with double wages and night diesel generator operations to finish before the monsoon rains.
2. **Expedited Freight Surcharges:** The contractor paid air freight or dedicated expedited truck convoys to deliver tracker steel from Mumbai to Bhadla instead of low-cost rail transport.

### Solution 8: Earned Schedule Across a Non-Linear S-Curve

#### 1. Identification of Bounding Periods
Given $EV = ₹6.25\text{ Crore}$:
Looking at the cumulative $PV$ table:
* $PV_4 = ₹4.50\text{ Crore}$
* $PV_5 = ₹8.00\text{ Crore}$
Because $PV_4 \le EV < PV_5$, the bounding period is **$C = 4$**.

#### 2. Linear Interpolation of $ES$
$$I = \frac{EV - PV_4}{PV_5 - PV_4} = \frac{6.25 - 4.50}{8.00 - 4.50} = \frac{1.75}{3.50} = 0.50\text{ months}$$
$$ES = C + I = 4.0 + 0.50 = 4.50\text{ months}$$

#### 3. $SV_t$ and Liquidated Damages (LD)
Given $AT = 6.0\text{ months}$:
$$SV_t = ES - AT = 4.50 - 6.00 = -1.50\text{ months}$$
* Delay in Days: $-1.50 \times 30 = -45\text{ calendar days}$.
* Prospective LD liability:
  $$\text{Potential LD} = 45\text{ days} \times ₹2,00,000/\text{day} = ₹90,00,000 \text{ (₹90 Lakhs)}$$

## 💻 Section C: Database, Go Engine & Frontend Implementation

### Solution 9: High-Precision Linear Interpolation Algorithm in Go

#### 1. Flat PV Interval Protection
If two periods have identical $PV$ (e.g., $PV_4 = PV_5$ due to a planned work stoppage), $\Delta PV = 0$. 
* The engine must check `if deltaPV > 0`. If `deltaPV == 0`, it must advance through subsequent periods or set fraction $I = 0.0$ to prevent a division-by-zero runtime error.

#### 2. Handling $EV > BAC$
If unapproved work pushes $EV$ beyond baseline $BAC$:
* The engine must clamp $ES$ to the total planned project duration ($ES = T_{\text{end}}$) and log an audit warning, or allow $ES$ to extrapolate if configured for forecasting.

### Solution 10: PostgreSQL Analytical Window Query for Rolling Variance Trends

```sql
WITH monthly_variances AS (
    SELECT 
        control_account_id,
        data_date,
        earned_value,
        actual_cost,
        planned_value,
        (earned_value - actual_cost) AS cv,
        (earned_value - planned_value) AS sv,
        LAG(earned_value - actual_cost, 1) OVER (
            PARTITION BY control_account_id 
            ORDER BY data_date
        ) AS prev_cv,
        LAG(earned_value - planned_value, 1) OVER (
            PARTITION BY control_account_id 
            ORDER BY data_date
        ) AS prev_sv
    FROM evm_periodic_snapshots
)
SELECT 
    control_account_id,
    data_date,
    cv AS current_cost_variance,
    prev_cv AS previous_cost_variance,
    (cv - COALESCE(prev_cv, cv)) AS delta_cost_variance,
    sv AS current_schedule_variance,
    prev_sv AS previous_schedule_variance,
    (sv - COALESCE(prev_sv, sv)) AS delta_schedule_variance,
    CASE 
        WHEN prev_cv IS NULL THEN 'BASELINE_START'
        WHEN (cv - prev_cv) > 500000 THEN 'IMPROVING'
        WHEN (cv - prev_cv) < -500000 THEN 'DETERIORATING'
        ELSE 'STABLE'
    END AS cost_trend
FROM monthly_variances
ORDER BY control_account_id, data_date;
```

### Solution 11: Next.js Variance Matrix Dashboard Component

```tsx
// components/EarnedScheduleBar.tsx
import React from 'react';

interface EarnedScheduleBarProps {
  actualTime: number;       // Elapsed months (e.g., 6.0)
  earnedSchedule: number;   // Earned schedule in months (e.g., 3.6)
  totalPlannedMonths: number; // Baseline total duration (e.g., 12.0)
}

export const EarnedScheduleBar: React.FC<EarnedScheduleBarProps> = ({
  actualTime,
  earnedSchedule,
  totalPlannedMonths,
}) => {
  const atPct = Math.min(100, Math.max(0, (actualTime / totalPlannedMonths) * 100));
  const esPct = Math.min(100, Math.max(0, (earnedSchedule / totalPlannedMonths) * 100));
  const isDelayed = earnedSchedule < actualTime;

  return (
    <div className="w-full space-y-1 font-mono text-xs">
      <div className="flex justify-between text-slate-400">
        <span>Timeline Progress</span>
        <span>

        </span>
        <span>Target ({totalPlannedMonths}m)</span>
      </div>
    </div>
  );
};
```

* **Severity Classification:** **P2 Warning**.
