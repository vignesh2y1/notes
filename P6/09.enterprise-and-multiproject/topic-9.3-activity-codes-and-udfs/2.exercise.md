## 🧠 Section A: Conceptual & Architectural Principles

### Question 1: Orthogonal Multi-Dimensional Slicing vs. WBS Churn
On the Surya 100MW Solar Project, the Chief Operating Officer wants to analyze progress grouped by **Contractor (Sterling & Wilson, L&T, Tata Power)** and then by **Physical Location (Block 01 to Block 32)**.
The Junior Scheduler suggests modifying the contractual Work Breakdown Structure (WBS) to reflect this hierarchy.
1. Why is altering the approved WBS to satisfy this ad-hoc reporting requirement considered a dangerous project controls failure?
2. Explain how Activity Codes solve this problem without modifying a single WBS code or altering CPM network dependencies.
3. Can an activity have multiple values assigned for the *same* Activity Code Type (e.g., both "Civil" and "Electrical" for Discipline)? Explain how P6 models cardinality between activities and code types.

### Question 6: Automated PostgreSQL JSONB Type Validation Trigger
In PostgreSQL, a `jsonb` column can technically store any arbitrary data type.
Write a PL/pgSQL trigger function `trg_fn_validate_activity_udfs()` that executes `BEFORE INSERT OR UPDATE` on `activity.udf_values`:
1. Reads all active field definitions from `udf_field_definition` for the `ACTIVITY` subject area.
2. Validates that if a numeric or cost field is present in `udf_values`, its JSON type is strictly a number.
3. Validates that if an indicator field is present, its value is restricted to `'RED'`, `'YELLOW'`, `'GREEN'`, or `'BLUE'`.
4. Validates that if a date field is present, its string value can be successfully parsed into a valid timestamp.
5. Throws a descriptive exception if type validation fails.
