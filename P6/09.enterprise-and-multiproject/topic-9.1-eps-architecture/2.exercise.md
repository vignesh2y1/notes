## 🧠 Section A: Conceptual & Architectural Principles

### Question 1: EPS vs. WBS Structural Invariants
A newly hired full-stack software engineer suggests merging the `eps_node` table and `wbs_node` table into a single unified `hierarchy_node` table with a `node_type` enum (`EPS` vs `WBS`).
1. State three fundamental architectural differences between EPS and WBS that argue against this unified database table.
2. In terms of CPM (Critical Path Method) execution, why can a WBS node have direct predecessor/successor relationships or rollup activity dates, whereas an EPS node cannot participate directly in CPM network forward/backward passes?
3. How does security assignment differ between an EPS node and a WBS node in enterprise governance?

### Question 2: Tree Storage Pattern Trade-offs in PostgreSQL
When designing the persistence layer for an enterprise scheduling backend supporting 50,000 projects across 5,000 EPS nodes:
1. Compare **Adjacency List**, **Nested Sets**, **PostgreSQL `ltree`**, and **Closure Table** across:
   - Read latency when querying an entire branch of depth 5;
   - Write throughput when inserting a new leaf node;
   - Complexity of reparenting an entire organizational division (e.g., moving Western Solar under a new Renewables Holding entity).
2. Explain how PostgreSQL's GiST index on an `ltree` column accelerates queries of the form:
   `SELECT * FROM project WHERE eps_path <@ 'SURYA.SOLAR.NORTH';`
3. Under what scenario would a hybrid architecture combining `ltree` and a `Closure Table` be justified?

### Question 3: Enterprise Default Inheritance & Override Lifecycle
During the creation of the *Surya 100MW Solar IPP Project*, the user selects EPS node `SOLAR-NORTH`.
1. Explain the difference between **static inheritance (snapshot copy)** and **dynamic inheritance (cascading lookup)** for:
   - Default workweek calendar;

   - Activity ID autonumbering prefix.

   - Existing active projects?
   - Future projects created under `SOLAR-NORTH`?
3. How do you prevent an "inheritance stampede" where a single administrative change at the root node triggers unversioned CPM schedule recalculations across 2,000 projects?
